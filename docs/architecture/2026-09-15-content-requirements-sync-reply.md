## 4. 必须更新的模块职责与状态归属

**战前永久进度与战斗历史分开。** `PlayerState` 保存首次赠证标记、教学步骤、角色等级／已学技能和真实库存。赠证与已确认的用卡／用证各自保证只记一次，并保存完成进度；正式战斗的入场基线取自这些操作完成之后。`BattleHistory` 不回退战前学习、用卡或赠证。战术物品自动使用开关也属于玩家偏好，恢复战斗数量时不覆盖它。战前 UI 的返回位置与弹层归客户端流程，不进入战斗规则。G01 中未完成的 16 教学只限制该场 Boss 开战，不锁住返回地图和已开放旧关；回刷后的等级写入长期进度，再入 16 时重新读取等级、库存与未完成步骤，不恢复到退出教学前的旧等级。

**一场 Boss 对应一个对局和跨面历史。** `BattleSession` 持有面序号、完整回合状态、待补配对、救援状态、敌我实例、有限上弦次数、随机／PRD，以及跨面的历史。完成当前回合后，先满足待补线，再判断翻面、最终胜利或救援：第一面双方全倒仍是“补线 → 翻面 → 第二面救援”；最终面双方全倒可“补线 → 胜利”，不强制复活。翻面携带我方状态，新敌实例读取新面定义、不复制旧壳 DOT；两个小工按实际先后读取更新后的 Boss HP，满血／死亡不扣恢复次数。

**结束一次尝试与发放一次收益统一处理。** 为每次尝试记录稳定标识，胜利入账或真正失败返还只确认一次；第一面完成、补线中、等待救援都不能触发整关结算。16 战前首证、整关首通第二证分别使用各自的领取记录，不能依赖同一个“进过关卡”标记。重复回调、重进结算页不重复发奖，正常胜利和广告通关共用结算入口，但经验计算模式不同。

**广告完成事实、权益及一次使用分开。** 广告接入只报告完成事实，业务模块据此记录权益；战斗历史引用一次权益的使用记录。恢复旧快照不能覆盖后来真实完成的广告，回退使用也只能恢复对应角色的一次机会。攻略的“本次挑战”需有跨重来／退出续玩的标识，与会重建的战斗尝试区分；通关结束在线更新权益，已保存攻略仍可回看。具体存档结构在架构中评审，不在此引入新数据库或供应商。

**固定槽位与存活射程分别计算。** 实例 ID 和原槽位稳定，死亡留空；存活顺序只用于相应主目标射程判断。火球在行动开始时保留原爆心槽位，只检查原左右邻位，不因死亡移动中心或跨空位。嘲讽检查本次所连活目标及合法受击条件；群盾检查其他存活队友，即使杀死最后一个敌人也不另加省盾条件；束缚检查所连活前排、可控性和下一阶段实际攻击。每种技能独立判断有效目标与 CD，不新增技能操作按钮。

**计算结果与输入／演出分开。** QFramework 的 `BattleSystem` 组织调用普通 C# `BattleSession`；后者唯一持有并计算战斗状态，返回有顺序的结果事件。DOT 在同一时点形成全场结果后处理死亡，避免动画播放顺序改变同归于尽；双射溢出事件不再抽随机或记贡献。输入、动画等待不推进回合，完整反馈结束前不接受下一次有效攻击；免费补线允许无存活角色操作。战前教学完成后播放准备与 Boss 登场，棋盘在输入期保持稳定。客户端、编辑器验证与攻略分别创建对局实例，共用规则实现与配置版本。
