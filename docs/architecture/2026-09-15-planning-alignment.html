2. 技能应该怎样进入架构

“被动 / 主动”是技能的玩法分类，“概率 / 冷却”是触发约束，不能只用一个泛泛的 SkillDefinition 把这些关系省略。

这里的“主动技能”指策划中的可释放专属技能，操作仍是解锁后随角色的连线行动自动施放，不增加独立按钮。用户已决定按技能分别判断本次是否施放，避免无效嘲讽消耗 CD。每名角色、每项带冷却的技能各自保存 CD；推进事件、入场状态与具体长度尚未确定，不从“单独计算”推导为只按本人行动递减。

技能 已定的触发方向 配置需要表达什么 仍缺什么
战士被动：暴击 概率触发，采用 PRD 判定事件、目标平均触发率、暴击效果参数 每行动还是每次实际攻击判定，概率与倍率
弓箭手被动：双射 概率连续射击两次，采用 PRD 判定事件、PRD 参数、追加攻击规则 第二发能触发哪些效果，毒箭怎样扣数量
盾骑士被动：格挡 概率减伤，采用 PRD 受击判定条件、PRD 参数、格挡效果量 每次受击怎样判定，毒是否可格挡
战士专属：嘲讽 本次攻击未杀死所连目标且技能可用时自动嘲讽；击杀后跳过 目标、技能距离、解锁条件、一敌方阶段期限；跳过不启动新 CD CD 如何递减、长度与入场状态
盾骑士专属：护盾 本次攻击击杀目标也仍按可用条件保护全部存活队友 存活队友目标集合、护盾量、一敌方阶段期限 CD 细则、重复护盾处理
法师、弓箭手其余技能 职业定位已有，完整技能未定 先确定技能内容，再确定参数 法师被动与专属技能、弓箭手专属技能

PRD 的“目标平均触发率”与首次判定概率不是必然相等的数。选定 PRD 算法后，由它把目标概率换算为逐次判定参数；当前不把演示的 50% 或任意概率序列写成正式数据。

本轮已确认：按技能自动判断

玩家通过选择角色和连线目标作取舍，不逐次点击技能、不额外选择另一个技能目标。战士的嘲讽仍以这次连线所对应的敌人为目标；盾骑士的护盾仍以全部存活队友为目标。

本次情况 自动处理 冷却处理
战士实际攻击击杀所连目标 跳过嘲讽 不启动本次嘲讽的新 CD
战士实际攻击后目标仍存活，嘲讽可用 自动嘲讽本次目标 实际施放后启动该技能 CD
战士只有技能可达，嘲讽可用 不造成攻击伤害，自动嘲讽，仍是一次行动 实际施放后启动该技能 CD
盾骑士实际攻击击杀目标，护盾可用 仍为存活队友施加护盾 按实际施放处理 CD，不套用战士的跳过条件
技能未解锁、仍在 CD 或不满足既有可用条件 不因“自动施放”绕过条件；可执行的攻击照常处理 不虚构一次新施放

“跳过技能不启动新 CD”与“已有 CD 是否随这次行动减少”是两件事；后者仍由 Q01 决定。

架构执行口径：先结算本次攻击的实际结果，再判断上述技能条件。 使用同一次攻击已经算出的伤害、暴击及减伤结果，不额外投骰、不以未结算的预计伤害代替目标存活状态，也不用等待 Unity 攻击动画播放完。这样不会因“预估能杀、实际没杀”漏放嘲讽。该执行口径是架构对用户意图的具体落实，与用户原话分开记录。

目前只将这一先后关系落实到战士嘲讽与盾骑士护盾。其他职业技能可能有自己的施放时机和条件，用户要求之后再讨论；不预设它们全部攻击后施放。一次玩家行动的适用效果处理完后再检查胜利，胜利时不额外执行敌方阶段。护盾未吸收伤害仍不计保护贡献。

配置、存档和对局状态分别保存什么

候选类 职责与代表字段 谁持有
ProfessionDefinition 职业 ID、等级属性表 ID、攻击距离、被动/专属技能 ID 只读 ConfigCatalog
SkillDefinition 技能 ID、被动/专属分类、目标、距离、效果类型与效果参数 只读 ConfigCatalog
PassiveTriggerDefinition 判定事件、PRD 配置引用；只在合法判定事件发生时试触发 SkillDefinition 的条件配置
ActiveCastDefinition 随连线自动施放、解锁要求、该技能的冷却配置引用 SkillDefinition 的条件配置
CooldownDefinition 冷却长度、推进事件、入场状态；实际施放才启动新 CD 带冷却技能的条件配置
CharacterRecord 等级、经验、已解锁技能、职业与装配选择 PlayerState，局外长期记录
SkillRuntimeState 每名角色每项带冷却技能的剩余冷却 CombatantState，当前对局
PrdState 每名角色、每项随机效果的积累状态 CombatantState.prdByEffect
SkillResolver 检查解锁/CD/射程，询问具体效果是否适用，再执行并更新 CD BattleRules 内部调用的纯 C# 规则
ISkillEffect 与具体效果 CanApply(context) 与 Resolve(context)；嘲讽检查目标仍存活，护盾检查存活队友 由 SkillResolver 按配置选择，类型与方法仍为候选

例如，冷却长度属于配置；“这个战士的嘲讽还剩多少次推进事件”属于对局。另一个战士、编辑器验证或在线搜索都各自持有运行状态。不要把剩余 CD 写回配置表，也不要在 QFramework Model 和规则对象中维护两份 CD。

被动的 PRD 仍由 prdByEffect 唯一持有，SkillRuntimeState 不再复制一份概率积累。技能 CD 与 PRD、随机数状态、血量、道具数量一起纳入回退和攻略输入。PRD 是否跨关保存属于 Q07；图稿目前没有擅自扩展长期存档格式。

一次技能相关行动的共同骨架

  1. 提交角色、目标与路径；规则同时检查路径、存活、攻击可用性、技能解锁/距离，以及已确定的技能可用条件。
  2. 无效行动不消耗物品、不推进 PRD 或 CD，也不推进敌方阶段。有效行动先记录可回退的起点。
  3. 当前战士/盾骑士先结算可执行的实际攻击，再按各自技能条件自动施放或跳过；实际施放才启动新 CD。攻击内部的被动/道具、其他职业技能与毒的顺序仍受 Q02、Q03、Q06 约束。
  4. 一次玩家行动的适用效果处理完后检查结果；未胜利才推进敌方阶段和状态期限。已有 CD 在后续确定的推进点递减；思考、画线和动画播放不会自行推进战斗时间。
  5. BattleSystem 将结果事件交给表现层。UI 显示概率说明和剩余 CD；UI 不独立投骰或计时裁定冷却完成。

3. 配置表要覆盖哪些内容

这里列的是逻辑表结构候选，不是已经创建的 Excel、ScriptableObject 或运行时文件。表格可以先由策划编辑，程序负责检查和导出；工作簿分几页、最终导成哪种格式属于后续技术选择。

逻辑配置 主键或引用 最小内容 已定与缺口
职业表 ProfessionDefinition professionId → levelStatsId、skillId 名称、攻击类型/距离、等级属性引用、默认被动、专属技能 四职业定位已记录，完整技能与初始开放顺序待补
职业等级属性表 HeroLevelStatsRow levelStatsId + level 最大生命、攻击、防御等属性；物攻/魔攻、双防是否拆列见 Q04 每一级的实际生命和属性从这里读取；正式值待调
升级经验表 GrowthLevelRow growthId + level 升到下一级所需经验 胜利经验与经验卡可成长已定，曲线与等级范围待补
技能表 SkillDefinition skillId 分类、目标/距离、效果、解锁要求、被动触发或专属施放规则 5 级 + 职业之证已定；概率、CD 与未定技能内容须补
PRD 配置 PrdDefinition prdId 目标平均触发率、选定算法需要的参数 独立积累和撤销重演已定；算法参数和生命周期见 Q07
状态配置 StatusDefinition statusId 施加效果、到期事件、持续量、叠加/刷新规则 嘲讽和护盾覆盖随后一个敌方阶段已定；毒见 Q03
敌人类型表 EnemyDefinition enemyTypeId 近战/远程/特殊定位、攻击类别/距离、行为与技能引用 类型与可见意图已定；完整行为与目标优先级待补
敌人数值档 EnemyStatsRow enemyStatsId → enemyTypeId 最大生命、攻击、防御及行为所需数值 同类型可在不同关卡引用不同档；不默认随玩家等级缩放
关卡敌人实例 EncounterEnemyEntry encounterId + pairId → enemyTypeId、enemyStatsId 对应颜色配对、排列位置、选用数值档、行动间隔/首次行动配置 每敌一对端点、固定敌人组已定；频率与目标细则待补
关卡与掉落 EncounterDefinition / RewardDefinition encounterId → boardId、rewardId 几何棋盘引用、推荐等级、基础经验、经验卡/职业之证/素材掉落 旧关可刷、失败不保留、胜利统一结算已定；数量/掉率待补
物品与战术物品 ItemDefinition / TacticalItemDefinition itemId 名称、类别、职业限制、触发条件、效果、来源 首版职业专属消耗品；每叠 99，一人一槽；永久装备延期
固定配方 RecipeDefinition recipeId → ingredientItemIds、outputItemId 材料 ID 与数量、成品数量 固定配方已接受；演示 24 个配方不是正式内容
结算与恢复 RewardPolicy / RecoveryPolicy policyId 贡献权重、等级修正、评分倍率公式参数、局外恢复时长 每角色独立经验公式已定；具体曲线及广告等价结算待补

同一种概念不能同时在多处成为可编辑真值。推荐首版以“职业 + 等级 → 一行实际属性”作为运行时来源；策划可用公式批量生成这些行，再调整特殊等级。运行时不再同时叠加另一套隐含成长公式。升级所需经验与升级后的战斗属性是两类数据，不能混为一张含义不清的成长参数表。

以下例子只展示查表关系，不编造正式生命值：

  • 一个 5 级战士：CharacterRecord 给出职业与等级 → ProfessionDefinition 找到 levelStatsId → 读取该表的 5 级属性行 → CombatStatBuilder 建立战斗属性；已解锁的技能与实际携带物品另行带入。
  • 第 8 关的红色敌人：关卡中该 pairId 引用一个 enemyTypeId 和 enemyStatsId → 读取该档生命与属性 → 建立独立 CombatantState。相同敌人类型在别的关卡可引用另一档，关卡不复制整份敌人行为。
  • 角色属性表的最大生命是初始能力；战斗中受到伤害后的当前生命属于 BattleState。表里不会把该敌人的生命从满值改为残血。

配置怎样与 QFramework、编辑器和攻略对接

候选链路：策划数据与关卡编辑资产 → 导出/校验 → 指定版本的 ConfigCatalog → QFramework ConfigSystem / 编辑器验证 / 在线攻略 → 各自的对局实例。

客户端 ConfigSystem 负责加载、校验并提供只读目录，CharacterSystem、EquipmentSystem、LevelSystem 和 BattleSystem 根据用途读取。ConfigSystem 不计算战斗、不持有当前生命；纯 C# 规则接收 ConfigCatalog，不反向寻找 QFramework 的全局 System。

基础 FlowPuzzle 编辑器继续保存棋盘与配对。候选 RPG 扩展选择敌人类型、数值档、行动配置与掉落，导出 EncounterDefinition；不把 RPG 表塞进 FlowLevelData。

必须检查重复 ID、引用不存在、关卡配对与敌人绑定不一致、引用职业等级缺行、技能缺失必要字段及规则版本不匹配。未填的正式数值应被报告为缺口，不能悄悄按 0 生命导出。已开始的对局使用固定配置版本，避免修改表后回退或攻略重演发生不同结果。

本轮不选择导表插件、热更新方案或网络协议，也不创建正式配置资产。先明确表里需要表达的规则和数值来源。

4. 交给策划会话的问题单

Q01—Q13 由策划会话组织讨论与记录；架构会话只标记依赖和接收结果。下列候选方案不代表用户已确认，也不应在架构会话中继续逐条追问。用户本轮已经确认的自动施放规则直接同步，其他职业技能留待策划后续讨论。

Q01 · 各技能独立的 CD，谁的行动使它恢复？

  • 已知： 技能随连线自动施放，每名角色、每项带冷却技能各自保存 CD；战士击杀目标后省去嘲讽，不启动新 CD。技能按钮和独立技能目标选择方案已被用户否定。
  • 具体问题： 战士用嘲讽后改用法师行动，战士的 CD 是否减少？入场是否就绪？本次释放的行动是否也抵扣冷却？“各自保存 CD”尚不能直接回答这些问题。
  • 候选与代价： 全队有效行动推进可鼓励换人；仅本人行动推进会要求本人再次出手。先前“全队有效行动推进、入场就绪”仍只是建议，用户未确认，不据本轮自动施放决定替用户选定。
  • 边界例子： 若定义“释放后还要完成 N 次后续全队行动”，释放这次不抵扣 N。N 次后续行动完成后，下一次选择该角色才可再施放。N 仅是说明口径，不是正式数值。
  • 还需明确： 技能 CD 中但普攻可达时能否只普攻；若普攻不可达且唯一技能在 CD 中，建议端点不可提交。影响 SkillRuntimeState、端点可用性、回退与攻略搜索。

Q02 · 一次双射到底判几次被动、扣几支毒箭？

  • 已知： 暴击、双射、格挡分别使用 PRD；飞斧超出原近战射程才扣，毒箭随符合条件的射击使用。
  • 具体问题： 被动按一次行动还是实际每发/每次受击判定？双射第二发能否再次触发双射？能否触发其他效果？只剩 1 支毒箭时两发分别怎样处理？
  • 建议： 第一发完成且目标仍存活时判一次双射，追加射击不再次触发自己；第一发已击杀则不追加、不扣第二发道具。暴击按具备暴击能力的角色实际攻击判，格挡按符合条件的实际受击判；这不让弓箭手凭空获得战士被动。毒箭按符合条件的实际每发扣，库存不足的其余发仍按普通攻击处理。这是候选，会比“每行动一支”消耗更快，需用户确认。目标已经中毒时是否继续消耗另随 Q03 确定。
  • 验收例子： 一次双射即使触发也不会无限追加；每一发能追溯是否使用毒箭、扣了几支及对应 PRD 变化。仅嘲讽没有实际攻击时不凭空判攻击被动。影响技能上下文、道具扣耗与事件顺序。

Q03 · 毒能否延后杀敌，延后击杀后固化哪条线？

  • 已知： 未击杀线路消失；击杀线路固化；毒伤与期限未定。嘲讽、护盾在随后一个敌方阶段结束到期。
  • 具体问题： 毒在敌人行动前还是后跳伤？能否致死？若上一步给 A 上毒，本步正在连 B，A 此时毒死，已经消失的 A 路线怎样处理？不能直接把 B 的线当作 A 的固化线。
  • 候选与代价： 同次连线内结算毒性附伤，击杀时线路归属明确，但失去持续磨血体验；持续毒削血但不直接致死，保留持续效果但不能靠毒收尾；允许后续毒杀，则必须决定占格变化。仅保存旧路线不能解决与后续固化路线重叠的问题。
  • 策划建议： 首版先采用“同次连线内的毒性附伤”，敌人持续毒伤玩法后续再定。该建议尚未确认，不能因实现方便就当作已定。毒蛇对队员的持续毒伤可单独讨论，因为队员死亡不涉及敌人的棋盘线路归属。若保留持续毒，还需确定护盾/格挡、叠加/刷新与阶段结算点。影响路径归属、状态结算、评分和攻略验证。

Q04 · 哪些属性影响伤害，同种敌人的强弱从哪里来？

  • 已知： 有等级、生命、攻击、防御；物理与法术有不同职业用途。正式属性清单和伤害公式尚未齐全。
  • 具体问题： 物理与法术分别用哪种攻击、防御属性？护盾在防御减伤前还是后吸收？等级只改变属性，还是也直接修正伤害？同一种敌人在不同关卡引用不同数值档，还是要求每只手填？
  • 建议： 用职业等级行与敌人数值档作为明确的属性来源，先由策划给两种伤害类型的公式草案及三组高/低防御对照例子；不额外引入攻速、命中率或按玩家等级自动缩放。
  • 影响与完成条件： StatBlock 字段、CombatStatBuilder、DamageEffect；策划需能说明“法师为何更适合这只高物防敌人”，并给出可计算例子。具体 HP/攻击值可以后续批量调。

Q05 · 第一版有哪些技能，什么时候教会玩家？

  • 已知： 最多三人；四职业定位；默认一个被动；5 级 + 职业之证解锁专属技能；第 10 关新职业、第 16 关首 Boss 是内容目标。
  • 具体问题： 初始是哪几种职业，第 10 关开哪种？法师的被动/专属和弓箭手的专属各是什么？第一枚职业之证在 Boss 前还是后取得？是否允许拥有或同时上场多个同职业角色？
  • 建议： 策划先交首版职业技能卡，每个技能只写触发、目标、效果、距离、解锁与是否 CD；然后给前 16 关教学顺序。若证书在首 Boss 后，必须提供不使用专属技能通过首 Boss 的验证条件。
  • 影响： 技能类型范围、角色实例与职业的关系、敌人配置与攻略参考条件。未来职业与演示技能不能自动进入首版。

Q06 · 已定职业自动施放与剩余结算顺序

  • 已关闭部分： 连线自动攻击与技能；战士本次实际击杀则跳过嘲讽、不启动新 CD；盾骑士仍按可用条件放盾。其他职业的技能自动判断以后分别讨论。
  • 执行口径： 当前这两项技能读取本次真实攻击结果；不做额外随机抽取或前置伤害猜测。已解锁、CD 就绪与既有距离/目标条件仍须满足。处理完本次玩家行动的适用效果再检查胜利。
  • 仍需明确： 其他职业的施放时机与适用条件；敌人行动顺序，击杀/状态变化后如何更新合法目标；行动间隔起算点、毒跳伤时点与重复护盾处理。
  • 验收例子： 战士暴击后击杀→无嘲讽且不启动新 CD；战士减伤后未击杀→可用时嘲讽；战士仅技能可达→仅嘲讽；盾骑士击杀→仍对存活队友放盾；技能在 CD 中→不绕过可用性。此为将来游戏规则的验收场景，本轮未运行游戏测试。
  • 架构影响： 在已有具体技能效果中表达适用判断，BattleRules 不设置“所有职业杀敌都禁用技能”的总开关。界面继续只提交角色、所连目标与路径。

Q07 · PRD 积累跨关、死亡和重来时保留吗？

  • 已知： 不同角色与被动独立；完全相同历史的撤销重演必须一致。
  • 具体问题： 连续未暴击后过关，下一关是否继续积累？死亡后广告复活是否保留？重来是回到本局初始随机状态还是重新开始随机序列？战术物品变化是否影响被动 PRD？
  • 建议： 同一尝试中的死亡/复活不清 PRD，重来恢复本局初始状态，可减少靠操作刷随机；跨关是否保留单独确认，它会决定是否写入长期存档。这里只给候选，不把跨关清零当作默认事实。
  • 影响： 随机状态保存位置、攻略适用性、重来与撤销的一致性。

Q08 · 全灭后继续复活，何时才返还本局消耗？

  • 已知： 失败、退出、重来返还本局消耗；失败不保留收益；战斗广告复活不限次数。
  • 具体问题： 全灭弹出失败界面后选择复活，是否继续同一次尝试？已消耗的两把飞斧是在弹窗时返还，还是结束该尝试时返还？
  • 建议： 区分“全灭等待选择”与“结束本次失败尝试”。复活继续时保留同一次尝试的状态与实际消耗；确认重来/退出时再按失败结算返还。必须经用户确认这一语义，避免既返还物品又保留其伤害结果。
  • 验收例子： 五把入场、用两把后全灭、复活继续并胜利，最终应明确扣多少；失败退出则回到入场五把。影响结算边界、历史及库存守恒。

Q09 · 广告直接通关的“正常经验”用什么基准？

  • 已知： 正常通关标记、正常收益，不贬损、不虚构伤害；仅扣已实际发生的物品消耗。
  • 具体问题： 开局就广告通关与已贡献大量伤害后通关，各角色评分倍率怎样定？已死角色的经验与局外恢复从哪里开始？
  • 候选： 为本关配置正常贡献基准，用于尚未发生的评分部分，并单独展示真实统计；或使用通过同规则验证的参考战斗得出等价奖励。前者需平衡数据，后者增加验证依赖。都需检查不能削掉已经取得的正常贡献待遇。
  • 所需产物： 策划给“开局跳关、已有贡献、有人死亡”三个结算例子。影响 RewardCalculator 的输入与 SettlementResult，不由 UI 伪造战斗过程。

Q10 · 回退跨过广告复活时，已看广告的权益怎样保留？

  • 已知： 回退恢复完整战斗历史，广告观看是已经发生的外部事件，局外真实时间不回退。
  • 具体问题： 先战斗死亡、看广告复活，再回退到死亡之前，复活权益是否可在同一尝试再次使用？重来是否还可使用？复活恢复满血还是指定比例？
  • 候选： 对局状态按历史恢复，将已获得权益单独记录，在选定范围内可重新应用；或规定明确的广告事件回退行为。需清楚告诉玩家，并避免重复发奖或无故损失已观看广告。
  • 影响： BattleHistory、广告完成记录、复活流程；不增加复活次数限制。

Q11 · 同关攻略的“再看”与“重新计算”怎样区分？

  • 已知： 每关一次免费提示，有有效完整攻略才消耗权益；同关重开可重看已获攻略；超时不等于无解。
  • 具体问题： 改路线、换队伍、升等级后，是重看旧攻略还是新计算？本关“免费一次”跨重来、跨天、旧关重打如何算？离线遇到不符合任何参考条件的阵容时显示什么？
  • 建议： 区分查看已获内容与对新状态求解；先列免费权益的作用范围，再决定重新求解如何收费。离线明确列适用条件与缺少条件，不承诺未验证的必胜路线。
  • 影响： HintAccessState、配置版本、参考攻略覆盖范围。在线超时与设备预算由架构任务实测，不让策划猜一个性能承诺。

Q12 · 首版道具和配方要补哪些正式内容？

  • 已知： 首版只有职业专属消耗品与固定配方，永久武器/护甲及强化延期；目录分类、排序与分页已经接受，不能重新列为未决。
  • 具体问题： 每个职业首版有哪些物品，各用哪些材料、一次产出多少、哪些关卡掉材料？多人可用同一物品但库存不足时，按阵容先后尽量补满还是平均分配？此问题先依赖 Q05 是否允许同职业多人。
  • 建议： 策划先给最小道具/配方/来源清单。若确有多人争用，先讨论按阵容顺序补满并明确显示实际数量，平均分配则需额外规则。现有示意数量均不转为正式值。
  • 影响： 配方、物品引用及 EquipmentRules；正式表填完可检查引用闭合与物品总量守恒。

Q13 · 队伍、战前准备与角色详情还差哪段交互？

  • 已知： 地图为主界面；冒险/队伍/背包三入口；连续关沿用阵容；缺货保留装配选择且可开战；合成返回原装配位置。
  • 具体问题： 换人与排序采用怎样的操作？角色详情怎样使用经验卡、展示技能解锁/CD 与恢复？战前查看敌人后如何回到原关卡？
  • 建议： 沿用已接受的目录风格，由策划补一个可点的“换人 → 调序 → 缺货去合成 → 返回 → 开战”示意及一个“升级 → 解锁技能”示意。
  • 影响： Controller、页面状态和业务 Command；不会改变战斗规则独立复用的职责划分。
