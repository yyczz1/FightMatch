## 1. 怎样读这张系统图

先看“输入与表现 → 应用流程 → 战斗与回退 → 结算协调 → 玩家长期资料”这条主线：玩家提出操作，应用流程组织步骤，战斗裁定当局结果，结算协调各负责系统完成长期入账。

箭头标明的是主要请求或数据交接，并非全部调用与返回。“战斗 → 结算”表示结果交接，结算调用由应用流程组织；“攻略 → 战斗”表示在独立局面中复用规则验证，不是让攻略操作玩家正在玩的对局。各业务读取配置、返回结果、保存数据的共性关系未全部画线，避免把职责图画成完整调用图。

“玩家长期资料”是图上的合并展示，其中**成长、背包、关卡进度仍分别有负责者**；不是新建一个万能系统。长期资料及配置在开战时提供入场依据，进行中的战斗拥有自己的局面。QFramework 继续组织 Unity 客户端，具体类与接口在后续系统设计中确定。

通用棋盘能力保留 FlowPuzzle 的几何职责；RPG 玩法组合它与战斗规则。编辑器与攻略可以使用这些规则验证内容，但不能因此修改真实玩家进度。图中“配置与内容”还涵盖内容生产入口，正文单列“内容编辑与验证”的职责；10 个展示节点不是实现模块数量。

## 2. 系统划分建议

| 系统职责 | 主要负责 | 与邻近职责的区别 |
| --- | --- | --- |
| 输入与表现 | 接收选人、连线和页面操作，显示状态及动画 | 不直接决定伤害、胜负、技能释放或发奖。 |
| 应用流程 | 组织入场、教学返回、对局、救援、退出与结算的交接 | 调用负责模块，自己不重算战斗规则或另存一套库存。 |
| 角色成长与职业 | 等级、经验、职业获得、技能学习、阵容和局外恢复 | 按配置提供角色基础属性，处理经验积累与升级；本场 HP、CD、异常归战斗。 |
| 背包与战术装配 | 物品与材料数量、合成操作、槽位与装配数量 | 按配置中的配方处理合成，维护真实库存；与本局携带量交接并保持数量守恒。 |
| 关卡进度与教学 | 关卡开放、首通、教学条件与步骤、一次性领取记录、挑战延续范围 | 判断教学与开战条件；应用流程组织赠证／学习，库存与成长各自修改数据。Boss 翻面不算新关。 |
| 战斗与回退 | 敌我状态、技能、行动、棋盘、面与阶段结果、完整历史 | 裁定同一对局中的规则；不直接改长期等级或发奖励。 |
| 结算协调 | 按已定奖励规则确定应得经验／掉落，组织消耗、首通和收益入账 | 战斗提供实际贡献，成长负责经验积累与升级；基础收益和后续自愿广告增益分别确认，均不重复入账。 |
| 广告权益 | 已完成广告对应的资格、适用对象、范围与使用状态 | 与广告播放接入分开；与战斗配合处理一次复活使用及撤销。 |
| 攻略 | 免费默认内容、当前局面分析、结果验证与适用性 | 使用独立局面和相同规则，不改变真实对局；失败不丢失已获在线权益。 |
| 配置与内容 | 职业、成长、技能、状态、敌人、关卡、物品、配方与奖励定义 | 提供一致的规则依据；不保存玩家当前 HP、库存或剩余 CD。 |
| 内容编辑与验证 | 编辑 RPG 内容，组合棋盘校验与战斗验证，产出带适用条件的关卡／默认攻略 | 保留基础 FlowPuzzle 编辑能力；使用独立验证局面，不接入真实玩家成长、库存或权益。 |
| 平台与保存 | 广告／网络接入，以及已确认数据的保存与恢复 | 提供能力，不越过业务负责者直接作出新的游戏结果。 |
| 通用棋盘能力 | 棋盘、路径、编辑与几何校验 | RPG 胜利还要经战斗规则验证，几何完成不等于任意队伍能获胜。 |

这是职责划分建议，具体实现为几个 QFramework System、普通 C# 模块或接入类留到后续设计。

技能在这套划分中有三个明确落点：**配置**定义主动／被动、触发条件、概率、CD 和效果参数；**成长**记录角色获得了什么职业、学会了什么技能；**战斗**统一处理当前技能是否可用、自动施放、被动触发、CD 与 PRD 变化。道具同样由配置定义、背包持有、战斗消费。首版装备仍是职业专属战术消耗品，永久装备与强化维持延期。

属性交接也只计算一次：成长按已定配置口径提供入场基础属性，战斗在此基础上管理本局状态及效果。不能让 UI、战斗和攻略各再套一遍成长公式；敌人的种类、档位与关卡实例来自配置，由战斗建立本局敌人状态。具体表结构与字段交给系统设计。

## 3. 状态归属表

“负责者”表示有权判断并提交该状态变化的业务职责。其他系统可提出请求或读取结果，UI 缓存和存档副本不获得第二份修改权。长期状态、当局状态和外部事实可能保存在同一存档中，回退范围仍然不同。

| 状态或事实 | 唯一负责者 | 谁可以请求变化 | 战斗回退与结束时的约束 |
| --- | --- | --- | --- |
| 长期等级、经验、已获得职业、已学技能 | 角色成长与职业 | 培养／学习流程、结算协调 | 不随战斗回退；入场资料与进行中的战斗明确交接。 |
| 阵容与局外恢复 | 角色成长与职业 | 队伍流程、战斗结束流程 | 战斗中的倒下由对局记录，结束时按规则交接为局外恢复。 |
| 背包、材料与局外装配数量 | 背包与战术装配 | 装配／合成／学习流程、结算协调 | 当局操作不逐次改这份长期账；已交给对局使用的同批物品不能在局外重复花费。 |
| 本局携带和剩余消耗品 | 战斗与回退 | 合法战斗操作、回退或结束流程 | 可随历史恢复；等待救援不返还，真正结束后与长期库存对齐。 |
| 道具自动使用开关 | 背包与战术装配 | 玩家主动切换 | 保留当前偏好，撤销数量时不擅自重新开启。 |
| 本局敌我实例、原阵位、HP、CD、PRD、异常、意图与能力次数 | 战斗与回退 | 合法行动、复活、回退等业务请求 | 原阵位与存活射程按既定规则分别使用；整体状态一致变化，表现坐标不决定技能目标。 |
| 本面棋盘、固化线、待补线、面序号和战斗阶段结果 | 战斗与回退 | 操作流程提出有效请求 | 两面属于同一对局，历史可跨面；应用流程依据其结果开放操作。 |
| 真实贡献、已用物品与本场待结算结果 | 战斗与回退 | 规则计算 | 只记录实际发生的内容；回退恢复对应历史，广告跳过部分不虚构贡献或消耗。 |
| 基础结算、失败返还与可选结算增益的办理结果 | 结算协调 | 应用结束／奖励流程 | 各步骤可辨认是否已完成；增益不重发基础奖励，不重复解锁职业或发首通证，失败返还也只交接一次。 |
| 关卡开放、首通与教学步骤、首次赠证记录 | 关卡进度与教学 | 入场教学流程、结算协调 | 战前赠证与最终首通分别记账；退出保留教学，战斗回退不撤销已确认的学习。 |
| 尚未通关的一次挑战及其延续关系 | 关卡进度与教学 | 应用入场／重来／退出流程、结算协调 | 按既定玩法跨重来和退出继续，通关后关闭；与本局尝试区分，供在线权益判断范围，不保存第二份战斗状态。 |
| 广告已完成事实与已获权益 | 广告权益 | 接入报告完成事实，相关业务申请兑现 | 完成事实不随战斗回退；权益按适用对象和范围使用，延迟回调不能误作用于另一场战斗。 |
| 本局一次复活的使用经过 | 战斗与回退 | 复活流程 | 回退跨过该使用时，向权益负责者交接恢复对应一次机会；战斗不另设一份独立可用权益账。 |
| 攻略内容及其适用局面 | 攻略 | 提示流程、网络分析返回 | 默认内容永久免费；旧状态的分析不能自动宣称适合新状态，验证不写真实对局。 |
| 职业、技能、数值、敌人与关卡定义 | 配置与内容 | 受控内容维护流程 | 一场对局及其回退、重演、验证使用一致依据；运行状态不回写配置。 |
| 内容编辑草稿与验证结果 | 内容编辑与验证 | 内容制作操作 | 草稿不能悄悄替换进行中对局的依据；验证结果带适用条件，不作为真实玩家的通关记录。 |
| 当前页面及跨系统流程的办理阶段 | 应用流程 | 用户操作及已确认业务结果 | 组织未完成交接的继续或终止；不从画面推断业务成功，不复制各系统的库存、学习或通关结论。 |
| 当前选中对象、动画播放进度 | 输入与表现 | 用户操作及已确认业务结果 | 只是呈现状态，不能据血条或动画回调自行判胜负和改库存。 |

## 4. 跨系统冲突检查清单

以下是本版**拟采用的架构约束与验收场景**，不是已运行的游戏测试，也不是重新让用户选择玩法。

| 编号 | 场景与涉及系统 | 最终裁定与交接 | 必须守住的结果 |
| --- | --- | --- | --- |
| A01 | 普攻、技能、DOT、护盾及动画共同影响 HP | 战斗统一结算；表现读取结果 | 同一伤害不重复扣血，播放顺序不决定死亡结果。 |
| A02 | Boss 清第一面、双方全倒、免费补线与救援 | 战斗确定面与阶段结果；应用流程开放补线、翻面、救援或结算 | 第一面全倒先补线再翻面救援；最终面可补线后胜利；整关只结算一次。 |
| A03 | 回退跨过技能、道具与广告复活 | 战斗恢复历史；权益负责者处理撤回的一次使用 | 恢复对应一次复活机会；不撤销看完广告事实、战前学习与用卡，也不变成无限复活。 |
| A04 | 道具消耗后全灭等待、复活继续、退出或重开 | 战斗报告实际消耗和结束情况；结算／退出流程与库存交接 | 等待救援不返还；结束才恢复或扣除对应数量；同批物品不被两边重复使用。 |
| A05 | 正常胜利／广告通关、后续结算增益与重复通知 | 结算协调区分基础结果和自愿增益，组织成长、库存、关卡进度入账 | 基础奖励不多发；增益只作用已定奖励范围，不重发首通证；广告直接通关的经验不套表现评分。 |
| A06 | 广告完成回调晚于退出、重开或切换页面 | 接入报告原用途；权益与相关业务校验对象和当前条件 | 保留已经获得的权益，不盲目复活当前页面里的另一个角色或给另一场战斗发奖。 |
| A07 | 攻略计算期间玩家继续行动、撤销或重开 | 攻略核对结果适用性；规则在独立局面中验证 | 过时结果不覆盖新局面；失败／超时／已证明无解分开；分析失败不再次收费。 |
| A08 | 配置数值变化、客户端运行与在线验证 | 配置提供一致依据；消费者明确本局采用的依据 | 同一局面不因使用不同定义得到不同结论；不在本轮选择格式、算法或部署方式。 |
| A09 | 16 教学时战士等级与卡不足，返回旧关升级后再进入 | 教学保留步骤；地图允许回刷；成长／库存各自保存；重新检查开战条件 | G01 指定见证可回刷恢复；不重复赠证、不锁死地图、不免等级、不强制广告。UI／存档和正式关卡仍待实际验收。 |
| A10 | 赠证、用卡／用证学习、合成在交接中中断或重复确认 | 应用流程组织操作；成长、库存和进度各自校验并修改负责数据 | 不能扣卡却丢经验、扣证却未学会、标记已领却未到账，重试也不能多领或多扣；完成判定与恢复办法须在共同契约中说明。 |
| A11 | 编辑器验证、默认攻略制作与真实游戏使用同一规则 | 内容编辑与验证组合几何能力和独立战斗局面；配置提供一致定义 | 几何可解不冒充 RPG 可通关；模拟不花玩家物品、发奖励或消费广告权益；既有通用编辑器仍可独立使用。 |
| A12 | 入场属性、战内道具开关与回退后重新行动 | 成长提供基础资料；应用流程传入当前操作条件；战斗统一计算 | 成长不重复套算；战斗不直接读取可变的局外模型；开关偏好保留，验证与重演须包含本次操作条件，不能只比较 HP 和线路。 |

## 5. 用四段流程检查职责能否接起来

1. **入场：** 应用流程向进度／教学取得条件 → 组织成长、背包、进度完成已确认操作 → 从当前资料和配置建立对局。每一步是否已经完成必须可识别；资料尚未交接完整时不能对外宣称已开战。回到地图也不能丢失已完成教学。
2. **行动：** 输入提交意图 → 应用流程检查当前是否允许操作 → 战斗判断合法性并完成规则计算 → 表现播放已确认结果，流程按阶段开放下一次操作。动画与无效操作不推进回合。
3. **回退：** 应用流程向对局提出撤销请求 → 对局恢复对应的完整历史并报告相关权益使用变化 → 权益负责者按已定规则处理一次机会 → 表现刷新。长期养成、已完成广告及当前开关偏好各按自己的范围保留。
4. **结束：** 对局提供最终结果或确认结束尝试 → 应用流程调用结算协调 → 成长、背包、进度各自处理 → 保存一致结果并确认完成 → 展示结算或返回地图。补线、第一面完成及等待救援都不能提前触发整关结算。后续自愿结算广告作用于这次已确定的奖励依据，不能重做整场基础结算；界面动画不成为下一关的业务等待条件。

这些是职责交接，不是方法调用时序或存储算法。系统设计会话再把请求、结果、生效时机、失败及重复处理写成双方共同遵守的具体契约。

**依赖方向采用以下约束。** 这里说的是职责如何使用彼此的能力，程序集和接口定义的放置另行设计。

| 发起方 | 使用什么能力 | 必须保持的方向 |
| --- | --- | --- |
| 输入与表现 | 向应用流程提交业务意图，读取已确认结果 | 不直接改成长、库存、战斗数据；血条／动画没有第二套裁定。 |
| 应用流程与结算协调 | 调用相应业务负责者和保存／平台能力 | 关键步骤有明确先后及完成判断，不靠事件监听顺序完成扣卡、学习或发奖。 |
| 各数据负责者 | 使用配置和交接来的资料处理自身规则 | 不相互修改内部状态；需要多方同时完成的操作交由对应流程组织。 |
| 战斗规则 | 使用本局资料、操作条件、只读规则定义和通用几何能力 | 不反向读取 UI、真实背包、广告接入或存档，也不调用结算发奖。 |
| 攻略及内容验证 | 在独立局面中使用同一战斗规则与几何能力 | 不能访问真实玩家的修改入口；默认参考与当前局面验证结果分开。 |
| 平台与保存 | 报告外部事实，存取业务确认的数据 | 不因收到广告回调或读到文件就自行升级角色、复活当前场景或裁定胜利。 |

道具开关是一个跨边界例子：玩家偏好归背包与装配，应用流程在行动提交时交给战斗本次采用的开关条件；战斗用它计算实际消耗，不主动查询局外模型。回退保留当前偏好。规则一致性比较的是相同局面、操作条件、配置与随机依据，而不是只比较相同路线。

一次**挑战**按已定在线权益范围延续到该关通关，一次**尝试**在重来时结束并重新建立；Boss 翻面和等待救援仍在原尝试内。关卡进度维护挑战关系，战斗维护尝试内状态，权益维护资格；应用流程组织交接。退出时按既定规则结束当前尝试并返还消耗，未完成挑战的在线权益仍保留；下次入场条件、恢复行为与权益适用性由各负责者共同契约说明，不用一个“是否在战斗中”替代所有范围。
