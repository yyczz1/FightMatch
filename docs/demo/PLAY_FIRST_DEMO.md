## 安装与启动

本轮尚未安装这两个APK；以下命令供恢复验收时使用，不是已执行的成功记录。先连接现有BlueStacks的本地ADB，或通过USB连接并在手机上允许调试；用`adb devices -l`读取实际序列号。

本机ADB路径：

```text
/Volumes/WD_BLACK_SN7100_2TB_Media/Applications/Unity/Hub/Editor/2022.3.18f1/PlaybackEngines/AndroidPlayer/SDK/platform-tools/adb
```

在项目根目录执行下列命令时，`adb`代表上述完整路径；将`实际序列号`替换为设备列表中的值。先检查既存包，再用`install -r`保留资料安装；若有签名冲突或降级拒绝，保留安装和资料，先核身份，不卸载、不清数据。

```sh
adb devices -l
adb -s 实际序列号 shell pm path com.yyczz1.fightmatch
adb -s 实际序列号 install -r "Builds/FMDemo029/mac-r1/019/fightmatch-demo.apk"
adb -s 实际序列号 shell am start -n com.yyczz1.fightmatch/com.unity3d.player.UnityPlayerActivity
```

也可在设备安装后从应用列表打开FightMatch。安装命令成功、应用启动、画面可读和业务流程成功是不同结果，需要分别检查。

## 第一次打开与已有资料

- 真正空根会显示“创建本机资料”，明确点击后生成一份本机冒险资料。
- 上次创建未完成时选择“继续原创建”；已有活动资料会读取同一资料。
- 若提示发现已有资料或保存受阻，保留数据，使用“重新读取”及当前提供的原保存恢复入口。
- 菜单中的格式升级是明确操作，按界面当前版本逐次检查并确认。已有资料不会为了Demo自动重建。

## 地图、队伍与背包

通过“地图冒险”“队伍”“背包”查看同一份资料。首段已发布内容为L1、初始角色W与两个空槽；队伍调整须检查并确认。背包显示真实库存和原操作记录，当前没有发布配方时显示空态。

从地图选择已开放关卡，在准备页确认当前阵容和入场条件。战斗不会替玩家自动选中角色；先点击一个存活成员，再在棋盘从端点沿相邻格拖到配对端点并松开，合法路线由既有规则处理。短按端点或固化线可定位关联历史；回退需检查界面列出的范围并确认。

“开局默认参考”显示已有正式参考；开始实际拖线后关闭参考覆盖。敌我行动可按节拍观看，也可点击“跳到当前战局”；暂停或失焦会结束当前表现播放并保留原业务结果。

## 胜利、结果与继续挑战

正常胜利先保存战局，完成或明确跳过最后播放后，再按“继续基础奖励结算”。结果页展示原收据中的经验、材料和结束记录；首段的基础奖励为20经验与2锡片，实际等级和剩余经验以当前资料为准。

结果页可“回地图”“查看当前队伍”“查看当前背包”，或“重新入场挑战本关”。“按原开局重来…”与“退出本局…”都需要确认；前者沿原入场基线重开战斗，后者明确结束当前局。它们与退出整个应用不同。

背包可选择原操作并“查看选中的原结果”，读取既有收据。没有开放且已发布的下一关时，本内容段结束；不展示虚构下一关或奖励。

## 保存与关闭重开

“返回 / 退出应用”在根页打开退出确认；“留在游戏”取消。应用退出后重新打开，应恢复同一资料；活动局恢复和已结算资料恢复需分别验证。本轮尚未完成Android上的这些冷启动见证。

保存不确定时，“重试原保存”“确认原保存结果”“继续选中的原保存”等按钮处理原请求。不要通过清除数据或卸载重装来解决或验证恢复。

产品数据位于系统实际`Application.persistentDataPath/FightMatch`，内部为`locator`与`profiles`。设备上的绝对路径须启动后实读；本文不把猜测路径当成已测事实。QA只使用隔离的`FightMatchQa029`数据根。
