## 2. R01：建议立即重来撤回旧尝试内的复活使用

### 已有依据及缺口

| 正式记录 | 原文依据 | 能确定什么 |
| --- | --- | --- |
| [主策划第 08 节](D:/Unity/UnityProj/FightMatch/docs/game-design/2026-09-14-fightmatch-game-design.md:213) | “重来就是从头重新开始本局，不保留本次尝试的战斗进度或失败收益。” | 战斗进度不保留；没有逐项写明广告使用是否撤回 |
| [广告回退条款](D:/Unity/UnityProj/FightMatch/docs/game-design/2026-09-14-fightmatch-game-design.md:215) | “回退到复活前时，那次权益恢复为该角色可直接使用的一次满血复活”；“未使用权益重来或退出也保留” | 撤回一次使用后恢复对应机会，未用机会跨重来／退出保留 |
| [三组规则](D:/Unity/UnityProj/FightMatch/docs/game-design/2026-09-15-three-group-recommendations.md:79) | “一次广告不在同一条未回退的历史上重复免费生效。” | 未撤回使用而再次死亡不能复用；不等于永久消耗后永不恢复 |
| [三组规则后文](D:/Unity/UnityProj/FightMatch/docs/game-design/2026-09-15-three-group-recommendations.md:81) | “重来同样保留已获得权益并重新开始战斗”，随后具体说明“尚未使用的该角色复活机会保留” | 较宽表述支持保留方向，但不足以单独证明所有已用机会随重来恢复 |

[Q10 接收](D:/Unity/UnityProj/FightMatch/docs/architecture/2026-09-15-content-requirements-sync-reply.md:41)关闭的是上面已有边界，没有替此次 R01 作出裁决。[共同契约第 14 节](D:/Unity/UnityProj/FightMatch/docs/system-design/2026-09-16/interaction-contracts.md:273)仍将 A 标为此前推荐，不能据此升级为用户决定。

### 比较与推荐

**推荐 B，待用户确认。** 真正执行立即重来时，放弃旧尝试全部战斗进度，撤回该尝试内仍有效的局内复活使用，保留原广告事实。每个对应角色机会恢复至可用一次，不累计为两个机会，也不自动给新尝试中的活角色再补血。

A 的直接重来会保持 g1 已用，但玩家先按已定规则撤销到 u1 之前再重来，g1 又明确可用。A 因而保留了按键顺序带来的收益差别，不能称为彻底防止跨尝试复用。B 消除这两条重来路径的差别；代价是玩家放弃旧战斗进度后，可在后续尝试再次使用同一广告机会。不能保留原尝试收益同时恢复机会。

**本建议只扩展立即重来。** 直接退出按当前历史结束，不自动撤回复活使用；这是对未裁决退出细节的推荐落实，连同 R01 一起确认，不伪称已有明确条款。先撤销使用再退出仍会保留已恢复的机会，和直接退出可能不同；这是保留现有撤销能力的结果，本稿不宣称所有操作路径都等价。若要连退出也自动恢复已用机会，应作为另一项明确扩展评审。

### 验收预期

下表中 B 专属结果均以获确认后的方案为条件；已有回退／未用保留／防重边界不待重选。

| 场景 | 预期结果 |
| --- | --- |
| g1 已通过 u1 复活，战士再次倒下，直接重来 | 撤回旧尝试中仍有效的 u1，g1 可用一次；新尝试角色状态按 R02，不能将这次入场初始化记作又消费 g1 |
| 先撤销到 u1 前，再重来 | 撤销已使 g1 可用；重来只保留，不再加一次，结果与上一行一致 |
| 广告完成，g1 尚未使用便重来 | 保留一份可用 g1，不重播广告、不自动使用 |
| u1 未撤回，角色再次倒下但继续本尝试 | g1 仍已用；无其他适用未用机会时需要新广告，不能因为再次死亡自动恢复 g1 |
| 使用后直接退出 | 本建议保持 u1 已用，倒下者按结束流程进入局外恢复；其他未用机会保留。不暗中把退出当成已执行一次撤销 |
| 连续两次重来，中间没有再使用机会 | 第一次撤回 u1，第二次没有可撤回的新使用，可用机会仍只有一个 |

| 重复完成回调、重复重来提交、旧 u1 的撤回晚到 | 同事实只生成一份机会；同使用只撤回一次。g1 已产生有效 u2 时，旧 u1 请求不能释放 u2；重试返回原操作结果 |

H05／H06／H07 应精确关联原机会、角色与一次使用，不能实现为“点击重来就把复活次数加一”。旧尝试关闭、新尝试建立和对应使用撤回的一致提交属于技术验收。R01 不裁定角色 HP，不能用“全部还原”替代 R02。

## 3. R02：按原入场资料立即重来，退出地图再入另算

### 依据与判定层级

直接依据是[主策划第 08 节的“从头重新开始本局”及永久资料不属战斗历史](D:/Unity/UnityProj/FightMatch/docs/game-design/2026-09-14-fightmatch-game-design.md:213)、[PRD 重来恢复入场状态](D:/Unity/UnityProj/FightMatch/docs/game-design/2026-09-14-fightmatch-game-design.md:428)，以及[三组规则的重来返还本次消耗](D:/Unity/UnityProj/FightMatch/docs/game-design/2026-09-15-three-group-recommendations.md:92)。

同时必须保留[原本恢复中的选中角色不参战、不自动换人](D:/Unity/UnityProj/FightMatch/docs/game-design/2026-09-14-fightmatch-game-design.md:57)，以及[全员不可出战时先调整阵容或恢复](D:/Unity/UnityProj/FightMatch/docs/game-design/2026-09-14-fightmatch-game-design.md:61)。[局外倒下恢复条款](D:/Unity/UnityProj/FightMatch/docs/game-design/2026-09-14-fightmatch-game-design.md:224)规定局外恢复，但没有明确要求“立即重来”先产生这个等待。

**内容侧认可架构推荐是现有“重来”的合理落实，状态为解释待联合复核。** 立即重来建立新尝试，沿用原本局入场的参与者、阵容槽位、基础属性、HP 初态、整关配置和随机初态；本次战斗倒下不先产生一份阻塞重来的局外恢复。它从本局开头重试，不能解释为继续保留后半局进度的免费复活。

这不是“用户已逐字批准所有字段”的声明。建议由主策划／SD00 联合签收并补全 H02／H06，无需再要求用户为常规重来回答一次玩法问卷。若有人主张先让本次倒下者等待恢复，则应明确标为新的体验取舍并请用户确认，不能以技术实现方便代替决定。

### 验收预期

| 场景 | 按上述解释的预期结果 |
| --- | --- |
| 原入场 W、M 均可出战；本次 W 倒下、M 存活；立即重来 | 两人恢复原入场 HP／参战状态，从本关第一面开头开始；不启动 W 的局外恢复，不因初始化 HP 消耗广告机会 |
| 原参战队伍全倒后立即重来 | 同样恢复原本可参战者的入场状态，可继续重试；不能暗中把“重来”变成必须先看复活广告 |
| 第一面重来 | 回本关最初棋盘、敌人组、我方初态；已有线路、伤害、CD／PRD 进展和待结算贡献清回原基线 |
| 第二面重来 | 回整关第一面，不以第二面为免费检查点；旧尝试无奖励，物品恢复整场入场数量 |
| 角色 X 入场时已在恢复、虽被选中却未参战 | 不把 X 加入原可参战集合，不因重来免费治疗 X；原有局外恢复按真实时间继续，不重置倒计时 |
| X 的真实恢复时间在本局内已经到期 | 不回退永久恢复结果，也不在原基线重来时擅自增加参战者；退出地图后按最新资料普通入场，再评估 X 是否参战。显示不能伪造仍在倒计时 |
| 先退出地图，再进入同关或另一关 | 退出结束原尝试，交接最终倒下者的局外恢复；普通入场读取最新长期资料。可用存活成员少人出战；全员不可出战则先调整、等待恢复或选择已有恢复途径 |
| 16 战前已领证、用卡、学嘲讽、完成用途说明，然后战斗中重来 | 上述永久操作均保留，不重领、不重扣、不重复要求学习；原入场基线本来就包含学会的嘲讽 |
| 入场后另有已经确认的永久经验增益到账 | 永久经验／等级保留，不能被重来覆盖；当前尝试及立即重来仍使用原入场等级和属性。退出地图后普通入场才使用最新资料，不为升级重算旧奖励或重抽原随机初态 |
| 连续重来或重来提交结果不明后重试 | 一次重来只建立一个新尝试；没有新收益、没有重复恢复事件或物品增发，查原结果后继续 |

“原入场基线固定”是本次建议的技术解释，不表示允许玩家在战斗中随时打开培养页面；永久增益晚到只是需要能正确处理的输入。原本未参战角色的真实恢复时间与永久增益都不能被旧快照覆盖。

代价是：立即重来暂不吸收入场后新增的永久属性或参战者，而退出地图重新进入会采用它们。这样保留同一关开头的可重演性，避免通过重来改变随机起点；界面需要区分“本局重来”与“返回地图”。若以后要让重来也重建全部最新资料，须连同随机、阵容、冻结物品和权益一起审阅，不能单系统暗换。

## 4. R03：建议保留同关同挑战的一次手动兑现

### 已定边界与当前缺口

| 来源 | 原文或既有约束 | 本轮处理 |
| --- | --- | --- |
| [主策划广告通关](D:/Unity/UnityProj/FightMatch/docs/game-design/2026-09-14-fightmatch-game-design.md:279) | “完成后按正常胜利处理：正常通关标记、解锁与关卡掉落” | 保留正常进度、掉落与首通处理 |
| [广告经验](D:/Unity/UnityProj/FightMatch/docs/game-design/2026-09-14-fightmatch-game-design.md:281) | “角色经验基准就是关卡基础经验，不应用评分倍率等战斗表现加成” | 不虚构贡献，不因迟到额外造一场奖励 |
| [真实消耗](D:/Unity/UnityProj/FightMatch/docs/game-design/2026-09-14-fightmatch-game-design.md:334) | “扣除本次尝试已经实际使用的次数，不为跳过的后续战斗额外虚构消耗” | 只处理实际被结算尝试的消耗 |

| [当前挑战定义](D:/Unity/UnityProj/FightMatch/docs/system-design/2026-09-16/interaction-contracts.md:14) | 按关保留未完成 ChallengeId，换关不覆盖原挑战；胜利关闭，下次重打新建 | 是当前系统设计解释，不是广告通关转用已获批准的依据 |
| [当前 H07](D:/Unity/UnityProj/FightMatch/docs/system-design/2026-09-16/interaction-contracts.md:185) | 广告通关目前绑定 AttemptId；目标封闭后保留未兑现状态并转 R03 | 这是待裁决的临时边界，不能当完整玩家处置方案 |

没有找到已明确选择“关闭后失效”或“可跨尝试兑现”的用户决定。在线攻略的 ChallengeId 权益不能直接套用为广告通关的已批准范围。[一次结算与竞争处理](D:/Unity/UnityProj/FightMatch/docs/system-design/2026-09-16/interaction-contracts.md:155)、[事实去重](D:/Unity/UnityProj/FightMatch/docs/system-design/2026-09-16/interaction-contracts.md:191)和[平台凭据边界](D:/Unity/UnityProj/FightMatch/docs/system-design/2026-09-16/interaction-contracts.md:193)仍是必须保留的技术约束。

### 推荐的完整方案（需要用户确认）

1. **原始归属不改。** 保留原 AdRequestId、广告完成事实、LevelId、ChallengeId 与发起尝试 A。若后来明确用在合法 B，另记录实际使用对象 B，不把原请求改写成在 B 发起。
2. **同关同挑战保留一次。** A 已退出或重来而挑战尚未通关时，资格可在同关、同 ChallengeId 的有效后续尝试中手动使用一次。可以跨换关暂存，不跨关兑现，也不能用于该关之后的新挑战。
3. **给明确入口。** 原关地图节点／战前展示已有通关机会，进入合法尝试后由玩家点“使用已获得的通关机会”。不自动切关、不自动结束 B、不要求再看同一用途的广告。正常教学、角色可出战等入场条件继续生效，不能借此跳过 16 的嘲讽教学。
4. **只结算实际兑现的 B。** 使用 B 的入场可出战参与者、绑定配置和实际消耗，按广告模式给基础经验、正常进度和掉落。A 已经以退出／重来结束，不复开 A 的结算、不追扣 A 已返物品，也不同时发 A 奖励。
5. **已经胜利则明确结案。** 原挑战已由正常或其他合法途径通关时，保留广告事实，标为“本次挑战目标已完成”并关联既有胜利结算；不再可用，不额外补奖、不换成货币／复活／结算倍率。不能伪造本资格已被使用，也不能把原正常奖励改成广告经验模式。
6. **按真实关闭原因处理。** 当前契约中换关不关闭未完成挑战，胜利才关闭，因此前两种结果覆盖正常生命周期。未来若新增未胜利就彻底关闭挑战的行为，必须先补资格处置；不能沿用错误码静默取消已取得的机会。

需要用户确认的是这整套边界，尤其“同挑战跨尝试手动用”“按 B 的参与者／配置／消耗结算”“目标已完成时不另给补偿”。不能只确认保留资格，却留下兑现对象和终止条件空白。

代价：H06／H07 要增加同挑战资格的适用检查、实际使用记录和入口。玩家退出 A 后可能用消耗更少、阵容或等级不同的 B 完成挑战，得到的经验参与者／实际消耗也可能变化；这是允许转用的真实收益变化，不能藏成纯技术修复。若坚持只限 A，就必须明确 A 关闭后的失效或补偿；直接失效会使按键／回执先后影响已看广告的收益，故不推荐。

### 验收预期

以下转用与结案结果均为推荐方案获确认后的预期，不是本轮已经修改的共同契约。

| 场景 | 预期结果 |
| --- | --- |
| A 仍有效，局面未变化 | 核验 A 当前资格和报告，使用、封闭、永久奖励一起完成；只有一次基础结果 |
| A 有新行动但仍有效 | 按当前局面重新核验并给必要的明确确认；确认前保留资格，不让旧修订直接结算 |
| A 已进入 WonPendingSettlement | 续办已形成的正常胜利结算；不能因永久奖励尚未到账就降为广告通关。此资格随后以目标已完成结案 |
| A 已正常胜利并结算 | 原正常奖励保持，记录目标已完成；不再发基础经验、掉落、首通证或解锁，不自动给补偿 |
| A 已退出地图，原挑战未通关 | A 按既有退出规则结束和返还，资格保留；回到同关同挑战建立合法 B 后可手动用一次 |
| A 立即重来为 B | 迟到回执只使资格可用，不自动结束 B；玩家明确点用后只结算 B。复活机会与 HP 分别按 R01／R02，不混成一种广告效果 |
| 当前已换到另一关 C | C 的状态和奖励不受影响；原关保留可用入口，返回原挑战后再用 |
| 原挑战已通关，玩家开始同关新挑战 D | 旧资格以原目标已完成结案，不能给 D 使用；LevelId 相同不足以授权 |
| 原挑战由另一个有效广告通关请求先完成 | 本资格同样以目标已完成结案；不同 AdRequestId 不能绕过同一挑战已胜利和一次基础结算 |
| 同一回执重复两次，或重复点用 | 一份事实、一份资格、最多一次有效使用或一个目标已完成终态；返回原办理结果，不生成第二份奖励 |
| 正常胜利与广告完成／兑现竞争 | 广告完成仅记录事实。正常最终行动已成功持久提交为 WonPendingSettlement 时续办正常结算；广告通关先联合提交成功则后续正常行动不能再结算。提交结果不明先查原操作，不凭未提交候选决定优先级。最多一个基础结果 |
| 退出／重来与广告兑现竞争 | 兑现先成功则已有胜利，旧退出／重来不能再次返还或建立同挑战 B；退出／重来先成功则资格进入同挑战手动可用，不追改已关闭 A |
| 崩溃发生在事实保存后、使用前 | 恢复一份资格，按原挑战现状显示使用入口或目标已完成，不依据当前画面猜兑现对象 |
| 提交结果不明，或发奖已保存但 UI 未显示 | 查询原操作结果：未提交才重试同操作；已提交只恢复显示，不新建使用、不再扣权或发奖 |
| 平台实际播放完成，但没有交付可核验凭据 | 不能靠页面残影发奖；是否能补录取决 SDK。此能力限制不能用来搪塞已经取得并保存的完成事实 |
| 广告通关后选择另一项结算广告增益 | 另一用途、另一请求，绑定实际通关 B 的 SettlementId；只发原固定 BaseReward 的一次增量，首通证／职业解锁不倍增，不自动连播 |
| 本广告以目标已完成结案，玩家随后另选增益广告 | 增益作用于既有正常胜利结算；不先将它降成广告基础经验，也不把未使用的通关资格直接换成增益 |

“可用”“已实际使用”“原目标已完成”必须有明确玩家结果，不能永久停在没有入口的 TargetClosed＋未兑现。具体持久化／重试结构由 SD00 和系统任务细化；没有凭据的外部事实补录属于平台能力前置，本稿没有验证任何 SDK。
