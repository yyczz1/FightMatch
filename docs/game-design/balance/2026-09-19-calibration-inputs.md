### 火球比较的固定前提

- 合法样本为标准无广告无卡路线16首通后W6／M5；战士已学嘲讽，第二枚通用证1枚，由玩家确认给法师学火球。不能将已学火球的样本冒充第一次进入9或16。
- 原物品关闭；比较固定为普通攻击被动未触发的确定分支，输入须显式记录，不把未触发伪装成关闭正式被动规则，也不保证所有PRD历史都能产生任意长的未触发序列。
- 现配置组中心0.8／周边0.4；高伤对照组1.0／0.6。攻击、目标、原槽、CD、路径、敌人状态全部相同，只切换整组系数；CD仍2。
- 按本表，本章火球不附烧伤，毒也不能附加。这是明确的试调输入，不是缺字段时临时返回0；泛用DOT验证仍保留，不能因此从规则模型删除DOT。
- 先验证9关和16两面的实际自动技能顺序、敌方行动、CD、免费补线及翻面。伤害片段仍见[原报告](README.md#火球同输入局部伤害与尚缺能力)，本轮未新增整场火球结果。

## 3. 状态来源与共享护盾的联合复核建议

以下细化不改变已定持续次数、较强伤害优先或护盾能挡DOT的规则，但会影响多角色评分归属，须由SD06／SD08接收后用于完整模型。

### 同类状态刷新

建议把“伤害来源”和“这次刷新者”分开记录。更强的新状态替换强度和伤害来源；更弱或相同强度只刷新持续次数，保留当前伤害来源。相同强度不靠先后遍历把整段伤害改归新角色；刷新行为本身暂不新增评分项目。

| 已有状态与新命中 | 建议结果 | 理由／代价 |
| --- | --- | --- |
| A施毒每跳4，W的新毒每跳2 | 仍4、重置3次，伤害来源A，记录W本次刷新 | 保留较强效果及归属；W仍可能消耗道具，沿用“已中毒也消耗”的规则 |
| A施毒4，W的新毒4 | 仍4、重置3次，伤害来源A | 避免同强度刷新抢走后续贡献；W不因此得到独立辅助分 |
| A施毒4，W的新毒6 | 改6、重置3次，伤害来源W | 强度与贡献来源一起替换，不用A身份承接W的更强伤害 |
| 原来源角色倒下 | 伤害继续按原来源归属 | 死亡不转移贡献；不要求施加者仍能行动 |

这里的4／2／6均为已完成施加计算的状态强度样例，不修改毒伤0.15攻击的候选系数。若未来允许临时属性增益，需要明确强度快照，不能每跳用当前选中角色属性重建。本稿建议在施加时固定可比较强度，目标侧适用修正仍按该跳既定规则；完整计算式由SD06落定。

### 同时DOT遇盾

建议以本批所有来源经过各自修正和既定伤害取整后的伤害 `q_i` 为输入，按比例分配护盾吸收，不设毒优先或烧伤优先：

`Q=Σq_i；S=min(可用护盾,Q)；s_i=S×q_i/Q；d_i=q_i−s_i`。

Q为0时各项均0。随后沿已定规则以同批前HP：`D=Σd_i；A=min(HP,D)；c_i=A×d_i/D`，D为0时贡献均0。盾内分摊和HP贡献保留精确值，不在中间新增floor。护盾来源只记真实吸收S，DOT施加者只记真实扣血c_i；未击穿的伤害不同时算敌方生命伤害。

例如HP5、盾3、毒4／火6：盾吸收毒1.2／火1.8，生命伤害依据2.8／4.2，实际生命贡献2／3；盾来源记3。相同条件盾8时只剩2点扣血，毒0.8／火1.2；盾10时生命贡献均0。调换展示顺序不改结果。

这只定义**已知一段护盾来源**的同批分摊建议，不偷定多段盾叠加、覆盖和消耗次序。首章无盾敌人不会遇到多段盾；后续三职业整场仍需给出实际各段盾来源和消耗规则。不能把暂缺来源的盾吸收算给当前行动角色。

## 4. 评分事件交接

沿用原试调权重：有效生命伤害1、盾吸收1、治疗1、格挡减免0.5、HP承伤0.25、束缚取消的真实攻击0.5、首章嘲讽有效改目标的远程基攻0.5。权重未重新调整。

每项交付：原尝试及内容依据、面／行动、原攻击或DOT批次、原效果来源、受益角色、目标、效果种类、已确定实际量。伤害／恢复量来自规则结果；显示文字只可用于本轮已知策划模型的审计，正式客户端不得解析动画文字计分。

| 项目 | 完整性及归属约束 |
| --- | --- |
| 普攻／火球／DOT | 保留逐目标及逐来源实际扣HP；超过HP的部分不计，克制不另乘评分 |
| 格挡→盾→HP | 已确定防御后的受击分段相加应还原该次可分解伤害；格挡归自身，盾归生成者，HP承伤归实际目标 |
| 嘲讽与承伤 | 按**同一次攻击、同一受益角色**取较大分值；不能跨全场只取一次最大值，也不能吞掉另一次普通受击 |
| 治疗／束缚 | 提供实际恢复量／被取消的准确攻击；空放、免疫、无攻击意图不给分 |
| 重复来源 | 同一完整报告内同来源同种类同受益者不能出现两次；拒绝重复条目，不用事件数量猜补分。真实业务重试由既有保存与操作结果规则处理 |
| 无事件与缺事件 | 本轮历史W/M无盾、无格挡、无治疗和无束缚，明确记录能力未启用；未知来源不是0，不能用这些样本验收K/A完整战斗 |
| 补线／翻面／复活动画 | 不凭表现生成贡献；复活、下一关满血与敌方上弦不记玩家治疗分 |

## 5. 本轮验证方法与限制

验证脚本 `verify_contribution_handoff.py` 只读取并重跑既有普通／Boss模型，原模型代码、配置及results不变。按原成长表每关入场资料回放，将真实逐次受击关联到场景／关卡／面／行动／攻击者；核对每角色伤害、承伤与生命变化、嘲讽转移次数及历史经验。无原来源或无法解释的事件文本时断言失败，不跳过未知事件。

对80行原成长输入分别计算“原伤害＋嘲讽”和“增加实际承伤并去重”的经验；它是**固定原等级与行动的敏感性对照**。新增经验没有传入下一关，不能据此声称战士更早升级、Boss新等级或80行成长已经重算。保留原样本中合法／反事实标记；未学嘲讽的16样本不转为合法教学。

整数经验采用仓库[数值研究§5](../../system-design/2026-09-17/numeric-random-research.md#5-log₂-的最少确定方向)的有理区间思路作离线样例证明：上下界floor一致才取整数，精确2的幂单独处理；区间仍跨界则验证失败，不加epsilon。此处不选择运行时表示、库、位宽、PRNG或性能预算。

原始正常经验先floor基础×等级修正×评分，结算广告再乘原倍率并floor。广告直接通关独立按基础经验，不套新评分；结算广告仍是另一步。G01必须仍14经验、W5＋6。

第3节新建议仅做明示输入的算术向量，未实现状态刷新、护盾业务提交、DOT完整战斗或持久化；其通过不能被引用为SD06已经接受建议。报告见同目录 `contribution_handoff_report.json`，执行证据完成后补入下节。

## 6. 执行结果与下一交接

实际执行80组原入场资料，共316次行动（263次普通关、53次Boss）、602条贡献事件，覆盖120个角色结算。原伤害＋嘲讽经验与历史120项全部吻合；增加承伤并按同次受击去重后，72项整数经验变化。构造边界和整批核验共21项通过；来源缺失、受击关联缺失及负数事件拒绝，既定DOT比例与建议的单盾分摊分开标记。

以下均取标准无广告无卡分支的原入场属性，法师数值保持原值；本表不把新增经验累计到后续关卡。

| 关卡 | 战士原贡献→候选贡献 | 战士原经验→候选经验 | 解释 |
| --- | --- | --- | --- |
| 1 | 30→31.25 | 25→26 | 实际受5点伤，增加1.25承伤分 |
| 8 | 52→68.75 | 43→48 | 固定原6行动，承伤项的影响较明显 |
| 9 | 32→37.25 | 38→41 | 法师仍32经验；没有用承伤贡献扣减法师的基础经验 |
| 12 | 49→54.25 | 48→50 | 原先先杀小工的标准路线，与N1留下小工的测试路线分开 |
| 16 | 118→127.5 | 157→162 | 11行动原路线；有效嘲讽对应的承伤分没有再次相加，法师仍161经验 |

G01单人W4回刷1：2行动、真实伤害30、承伤5，原贡献30／候选31.25，两者都得到14经验，仍到W5＋6。标准分支16个固定关卡的战士经验差合计43，仅作敏感性摘要，**不是新成长最终多43经验的结论**；提前升级会改变后续伤害、受击和等级衰减，完整重算后才可判断。

内容判断：0.25承伤项确实给前排更多经验，但此样本不足以认定战士已经过强；目前不降权重、不设承伤上限。下一次真实成长重算须同时观察战士提前升级、法师相对等级、Boss生命余量及行动数，避免只按本表的固定输入差额改经验曲线。

整数经验的120项原值与120项候选值均在12项级数界内确定同一floor；这是本批有限样例的证明，不是任意输入的终止或手机性能保证。正常G01经验14经2.2结算倍率为30；广告直接通关示例基础20经2.2为44，两者独立，未执行真实广告服务。

执行命令：`python -B docs/game-design/balance/verify_contribution_handoff.py`。脚本只向标准输出给完整JSON；报告保存了80行对照、602条带来源的事件和输入SHA，供逐项复核。来源键是这批离线审计的定位方式，不要求程序另建一套ID或解析这些文本。

N2-F仍需SD06将上述首章试调资料与实际效果／随机条件接到同一回放规则；N2-S已具备可复核的内容字段与固定输入算例，完整角色模型仍须实际产出来源事件。状态归属和盾分摊建议由SD06／SD08接收，SD00维护共享稿；不新建任务、不自动发送协调消息，也不要求用户重新回答原有玩法。
