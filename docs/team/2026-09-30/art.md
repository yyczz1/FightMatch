## 3. uGUI 画面基线

### 3.1 Canvas 与安全区

- 竖屏基准：`540×960`；根 `CanvasScaler` 使用 `Scale With Screen Size`，参考分辨率 `540×960`，`Match Width Or Height = 0.5`。这延续现有参考尺寸，不沿用旧 `PanelSettings` 运行时依赖。
- 背景层允许延伸到整屏；所有文字、按钮、棋盘命中区、角色状态和弹窗正文必须位于 `Screen.safeArea` 映射的 `SafeAreaRoot` 内。
- 设计坐标按安全区内部计算。宽屏／长屏优先增加背景留白，不拉伸人物、图标或棋盘；安全区高度不足时先压缩舞台留白，再压缩非交互装饰，不缩小触摸热区和正文到下限以下。
- 首轮必须至少检查 `540×960`、`1080×2400` 和带非零四边 inset 的模拟安全区；最终 Android 仍以实际设备截图为准。
- 场景仅有一个 `EventSystem`；Canvas 有 `GraphicRaycaster`。非交互装饰的 `Raycast Target` 关闭；模态遮罩独占点击并阻断其后层。

### 3.2 分层顺序

同一根 Canvas 下按下列 sibling／sorting 顺序装配，名称是跨线接口，不要求主程照抄类名：

1. `BackgroundLayer`：全屏色底、环境背景；不得参与命中。
2. `ScreenLayer`：当前页面主体；地图／队伍／背包／入场／战斗／结算每次只显示当前页。
3. `HudLayer`：固定页头、战斗角色状态、操作栏；其透明区域不得吞棋盘事件。
4. `PopupLayer`：普通确认、详情、保存恢复、语言／更新提示；显示时带全屏阻断层。
5. `SystemLayer`：启动读取、不可恢复错误、调试诊断；不得被普通弹窗盖住。

页面切换、保存、战斗及结算语义由现有 Application／Controller 决定；美术层不得另建第二套流程状态。

## 4. 战斗页参考布局

基准安全区 `540×960` 时使用下列可伸缩槽位；它们是装配约束，不是最终主题皮肤：

| 区域 | 参考尺寸／约束 | 内容与遮挡规则 |
| --- | --- | --- |
| `TopBar` | 高 56；左右内边距 16 | 返回／标题／设置或状态入口；按钮热区至少 48×48 |
| `Stage` | 高 190；左右内边距 16 | 敌我横向相对；最多三名队员与本面敌人使用固定槽位，倒下后保留空档，不因视觉重排改变射程序号 |
| `BattleStatus` | 高 48；左右内边距 16 | 当前阶段、意图、播放／保存状态；单行优先，必要时两行，不覆盖角色头部或棋盘 |
| `BoardFrame` | 正方形；基准 `508×508`，即安全宽度减 32 | 棋盘格、端点、路线、回退／参考覆盖；背景装饰不得像可交互格，视觉坐标必须服从真实棋盘几何 |
| `BottomHud` | 剩余约 142；左右内边距 16，底部 8 | 角色选择卡／当前角色、有限操作入口和状态；确切按钮由主策页面映射与主程行为表确定 |

适配优先级：保持棋盘正方形和命中一致 → 保持 48×48 热区 → 保持正文可读 → 压缩 Stage 空白／装饰。`BoardFrame` 不因背景草格、边框厚度或角色素材改变业务坐标。

### 4.1 舞台与角色接口

- 舞台分 `AllySlots` 与 `EnemySlots`；双方各保留最多三个固定底部中心锚点。斜向错位仅表达前后层次，不产生自由九宫格布阵规则。
- 每个 `ActorSlot` 的逻辑脚点为底部中心；角色可见内容基准上限约 `120×168`，四周至少留 8 像素空隙，武器／发条钥匙不得进入相邻角色的状态文字区。
- 角色 HP、意图、目标和状态图标属于独立 HUD 子层，不烘焙进角色图。角色死亡后槽位保留，倒下表现不得把邻位拖到原位置。
- 战斗角色的具体播放器保持可替换：静态 `UnityEngine.UI.Image` 灰盒、Unity 2D 部件动画或后续获批方案都挂在同一槽位接口；本规范不批准 Spine 或新的动画包。
- 当前试玩占位用单色剪影＋`PLACEHOLDER`／诊断标签，禁止使用两批未采用候选。占位只证明装配，不能进入最终商店图或美术验收。

### 4.2 棋盘与 HUD

- 棋盘边框与内部可玩区域分开；外框可以九宫格拉伸，内部格、端点、路线由程序按真实数据绘制。
- 端点、线路、固化线、免费补线、提示预览必须有形状／明度冗余，不能只靠红绿等颜色区分。线路上方不叠高对比纹理。
- 角色选择卡建议 72 高、最多三卡横排；像素头像方向后续若采用，使用独立头像资源，不从战斗角色截图自动缩放。
- 普通操作按钮热区至少 `48×48`，相邻热区净距至少 8；装饰性 Image 关闭 Raycast Target。按钮禁用态同时降低明度与饱和度，不能只降低透明度到难以识别。
- 播放、参考演示、回退预览与实际输入使用同一棋盘框；覆盖层只改变表现，不偏移实际端点或拦截不该拦截的取消事件。

## 5. 页面、弹窗与文字留白

- 地图、队伍、背包、入场、结算采用同一 `TopBar + Content + BottomAction` 骨架；长列表使用 ScrollRect，由主程按 uGUI ScrollView 规范实现，不把整个页面缩小塞进一屏。
- 普通居中弹窗最大宽 `476`，距安全区四边至少 32；长正文视口在 540×960 下至少容纳五行英语，仍超高时仅正文区滚动，标题和主／次按钮保持可见。危险／不可逆操作保留明确主次按钮，不用仅靠颜色表示。
- 结算页常设奖励说明区必须明确容纳“首次通关奖励”标签；不能以飘字或一次性 toast 代替。更新下载完成提示在地图等自然页面边界出现，并提供稍后处理位置。
- 字体目标为 TextMeshPro；具体 Font Asset 与中英文字形由主程核兼容性和许可。建议层级：页标题 28、分区标题 24、正文／主按钮 22、辅助标签 18，最小正文不低于 18（均为 540×960 参考坐标）。
- 英文按钮／标题先按简中同义文案宽度的 `1.35×` 作为最低留白起点，再用 `planning-localization-draft.csv` 的实际文本测量；该系数不是截断上限。长按钮改为全宽纵排或把高度增到 56／64，允许受控两行，不用缩字号硬塞。数字、物品名和动态参数用模板插槽，避免固定宽度遮挡。
- 当前最长英语正文必须作为容量样本：`fm.guest_local_only.body` 191 字符、`fm.battle.restart.preview_body` 163、`fm.battle.exit.preview_body` 119、`fm.save_recovery.end_uncommitted_confirm` 116、`fm.save_recovery.unknown` 115；不强求同屏全文，允许正文滚动，但主语义与动作按钮不得被折叠或改成内部术语。最长带参数摘要用 `fm.initial_download.summary` 验证。
- 所有玩家可见 Prefab 文字默认值统一为明显诊断占位，如 `【if you see this, it is a bug.】`；运行时从 Luban 文本表经项目自有绑定替换。灰盒原型图中的说明文字不代表 Prefab 默认文案。
