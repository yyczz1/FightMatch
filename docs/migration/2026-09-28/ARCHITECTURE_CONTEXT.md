## 必须保留的决定

- **一个权威写入者。** 配置定义、永久玩家进度、当前对局、广告完成事实、UI 状态分开生命周期。显示缓存和存档副本不能成为第二套可独立修改的业务真值。
- **请求与结果分开。** 输入/页面提出意图；负责系统判合法、计算、提交后再报告事实。动画顺序、事件监听顺序和广告回调都不能直接裁定战斗或永久奖励。
- **协调有边界。** 应用流程组织跨系统步骤，战斗统一裁定对局，结算负责永久收益交接。角色成长、库存和进度仍各有归属，不把它们收进一个万能应用模块。
- **同一规则，不同局面。** QFramework 组织 Unity 客户端；纯 C# 业务规则可由游戏、内容验证和攻略共用。攻略在独立状态上验证，不修改真实对局。FlowPuzzle 继续负责几何解题，FightMatch 组合 RPG 规则；保留 solution-first、不查唯一解、不要求铺满全板、Core/Editor 分离。
- **跨系统提交有明确完成点。** 后续系统设计选择的候选整体、持久化后发布、重试/未知结果门、物品份额及战斗历史规则按现行具体契约执行。UI 返回不能隐式再次花费或提交；战斗回退不能回滚永久学习与广告已完成事实。
- **Demo/Android 连续建设。** 发布内容集合、输入设备、保存目录、时间/熵/生命周期和 SDK 适配可以不同；业务规则、正常玩家入口、身份与存档语义沿同一产品继续。不能做独立 Demo 业务核再重写 Android。

## 跨设备的准确边界

原架构最后正式回合 `01a0ad90-45eb-7e33-9596-53934e8f94be` 已 completed，用户确认**进行中的战斗不做跨设备同步**。原设备保存本局并可继续；新设备使用已同步局外进度，广告权益依既定规则保护。出处为 [交接记录](../../handoffs/2026-09-17-system-design.md)及 [正式回执摘录](conversation-receipts.json)。具体后续实现以 [cloud-sync](../../system-design/2026-09-16/details/cloud-sync.md)、[ad-entitlements](../../system-design/2026-09-16/details/ad-entitlements.md)和有效任务包为准。

这条游戏产品规则与本次“开发者从 Windows 换到 Mac、用 Git 取回源代码和设计”是两件事。源代码迁移成功不能证明玩家云存档、广告 SDK 或跨平台强保存已经接入；不因迁移改变既有同步范围。
