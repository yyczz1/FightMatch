## 2. R01：重来是否撤回本次尝试中已经使用的复活机会

**具体场景：** 战士倒下 → 完成广告获得机会 g1 → 使用 g1 满血复活（使用记录 u1）→ 战士再次倒下 → 玩家点“重来”。

已定来源：[主策划第 07～09 节](../../game-design/2026-09-14-fightmatch-game-design.md)、[三组规则“撤销与广告复活”](../../game-design/2026-09-15-three-group-recommendations.md)、[Q10 接收记录](../../architecture/2026-09-15-content-requirements-sync-reply.md)。已明确跨使用回退恢复一次、再次死亡不自动复用、未用机会保留；没有找到直接规定“重来是否等同撤回已用记录”的条款。

| 可选口径 | 玩家结果与契约影响 |
| --- | --- |
| A：保留已用记录 | 直接重来后 g1 仍已用；新的尝试再倒下需要其他未用机会或新广告。现共同契约把它列为此前推荐，但尚未裁决。 |
| B：撤回旧尝试内的使用 | 重来后 u1 被撤回，g1 恢复可用；每条未回退的实际历史中仍只能使用一次。重来会清掉本局进度，不能保留原战斗收益再免费使用。 |

**必须一起比较的路径：** 按已定回退规则，玩家可先撤销到 u1 前，使 g1 可用，再点重来，此时它属于明确应保留的“未用机会”。因此 A 与“先撤销再重来”会有不同结果；A 不能被描述成已彻底防止跨尝试重复使用。请策划判断这种差别是否符合预期，或 B 更符合从头重来的体验。

请覆盖：直接重来；先撤销使用再重来；广告完成但尚未用便重来；复活未撤回而再次倒下；使用后直接退出；连续两次重来和重复回调。明确对一次局内使用的处理，不扩成可交易或通用复活道具。

影响：H05／H06／H07、A03／A04；战斗历史、权益、结算与重来流程。架构可支持两种口径，但不能由各系统各选。

## 3. R02：立即重来与退出地图再入的角色状态

**具体场景：** 战士、法师以可出战状态进入 16；战士在本次战斗倒下，法师存活；玩家立即重来。

已定来源同主策划第 07～09 节及三组规则：重来从头开始本局、PRD 与物品恢复入场状态；退出或最终结束时交接局外恢复。当前没有逐项说明立即重来是否先触发倒下角色的局外恢复。

架构推荐将立即重来解释为：使用原入场队伍、属性、HP 初态、配置和随机初态，创建新的尝试；本次倒下不先转成阻塞重开的局外恢复。战前已经完成的用卡／学习仍是永久事实，现实时间不回退。若先退出地图，则按结束交接局外恢复，下次进入读取最新长期资料。

请复核这是现有“从头重新开始”的准确落实，还是仍需要用户决定。若要求重来先等待恢复，请说明全灭玩家点击“重来”后的可操作结果；不能界面叫重来，却在未说明情况下变成必须看广告才能继续。

请覆盖：一人倒下、全队倒下、第一面／第二面重来；入场时已在恢复而未参战的选中角色（不能因重来无条件恢复）；退出地图再入；战前学习完成后重来；进入本局后收到的永久经验增益（本局入场资料是否保持原基线）。

影响：H02／H06、成长恢复、战斗入场与应用流程。R02 与 R01 分别描述角色入场状态和权益使用，不可用一句“全部还原”混在一起处理。

## 4. R03：原尝试关闭后才收到广告通关完成事实

**具体场景：** 玩家为尝试 A 发起广告直接通关；完成回执较晚到达，在此前玩家已退出、重来为 B，或正常通关 A。技术接入先保存原 AdRequestId／AttemptId／ChallengeId，因此仍能识别回执原属哪次请求。

已定来源：[主策划“广告直接通关”](../../game-design/2026-09-14-fightmatch-game-design.md)、[架构接收的广告与一次结算约束](../../architecture/2026-09-15-content-requirements-sync-reply.md)。正常进度／掉落及基础经验、不虚构消耗、重复回调不重复结算已明确；已结束对象的未兑现资格如何给玩家处理尚不明确。

| 当前情形 | 必须保留的结果 | 请求策划明确的部分 |
| --- | --- | --- |
| A 仍有效 | 用 A 的实际消耗和参与者核验后，原对象资格使用、结束与永久奖励一起完成。 | 局面已变化时的提示／确认方式可在系统详细设计落实。 |
| A 已正常胜利 | 保留广告完成事实及 A 已结算记录；不能再发一遍 A 的基础奖励、首通证或解锁。 | 广告效果是否视为目标已完成；若另有补偿，必须给明确依据与范围。 |
| A 已退出或重来为 B，同一挑战未通关 | 保留原事实与未兑现状态；不能自动给 B 或其他关卡通关。 | 是否允许玩家在同关同挑战的后续尝试上明确兑现一次，或采用其他有界补偿。 |
| 已换关、已关闭挑战 | 保留可核对的原请求／完成／处理记录，拒绝跨关自动使用。 | 若资格仍有可用范围，写清条件；若不再可用，给出明确玩家结果。 |

现契约在未裁决时返回原对象已关闭并保留未兑现状态。这是防止误发的临时技术边界，**不是“看完广告永久得不到结果”的完整产品方案**。此前“仅原尝试有效时兑现”的推荐需要连同上表后续处置一起复核。

候选方向：资格只绑定原尝试，并明确目标已完成／结束后的处理；或对退出／重来保留同关同挑战的一次手动兑现权（这会扩展当前 AttemptId 绑定，需共同修改 H06／H07）。请比较玩家收益和重复领取风险，不由程序自行赠送货币、转成复活或增加新广告。

接入限制：真实完成却在持久收到凭据前进程消失，能否补录取决广告平台；没有可核验事实不能靠页面状态发奖。这里请求的是“已拿到可核验完成事实”的业务口径，不要求策划保证 SDK 尚未提供的能力。

请覆盖：回执重复两次、正常胜利与回执竞争、退出、立即重来、换关、同关新挑战、崩溃恢复，以及原广告通关后的另一项自愿结算广告增益。基础奖励仍只能结算一次。

影响：H06／H07、A05／A06；平台报告事实，权益保存资格，战斗和结算核验具体兑现对象。
