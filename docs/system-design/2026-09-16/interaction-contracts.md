## 1. 身份、修订和公共资料

**启动与热更新范围补充：** 用户要求首场景精简，主要业务代码和资源通过热更新交付。启动层保留下载、校验、版本兼容、加载及失败恢复的最小能力，业务入口在完整代码集合可用后初始化；资源方案只采用YooAsset，代码加载采用HybridCLR，Addressables不并用。启动层不得静态依赖热更游戏类型，也不能因读取旧存档将业务规则复制进底座。首批预装范围、稳定跨层约定及版本／存档摘要的一致性仍待详细设计，见[会话计划第15节](session-plan.md#15-用户约束首场景精简主要业务热更新)。

**联网要求，优先于下文原本机流程中的网络假设：** 用户已确认一次广告机会使用时联网校验，断网保留、联网再用；已兑现到背包的物品仍可正常离线使用，战斗回退仍在本机完成。同一机会在撤回后再次使用也须联网核对准确使用状态，超时或未知不能视作新资格。许可、效果提交、撤回的交接及待解决恢复场景见[H14](runtime-extension-contracts.md#6-h14-一次广告机会的联网使用与精确撤回)，不能仅在原H07前加一次请求就宣称完成。[确认来源](session-plan.md#14-新增范围的研究图稿与本轮决定) · [职责扩展图](../../architecture/2026-09-16/c4/r2/README.md)

## 2. 一致提交、重复和错误语义

**先辨认完成对象，再解释状态。** H02～H08及玩家资料安装的`Completed`必须满足H10；H01完成的是内容及验证证据可取得的发布，返回ContentBinding和发布提交依据，不往玩家档塞制作事务；H09候选返回仅为验证结果，已保存内容另有本机提交。H11分别报告准备可用、代码入口可运行、业务恢复完成；H12～H14远端阶段返回扩展第2节的远端结果，本机安装仍用H10。调用方必须能从结果辨认是哪项操作／对象完成，不能消费一个无对象的success布尔值。拒绝是确定没有发生该项效果；网络超时、取消传输或没有回执均不足以证明拒绝。

H14固定奖励另有`ResultCommitted`：远端已对准确Grant／Use持久承诺同一份固定结果，允许后续本机安装，但还不是玩家业务Completed。承诺后本机未安装只能续办该结果，不能以本机NoEffect释放资格重新产生奖励。本地目标效果许可路径的未知问题仍单列，不把固定奖励顺序推广到复活／直接通关。

**共同推荐 D01：各负责者产生候选切片，整份一致版本保存后一次发布。** 不先扣卡再等待成长，不靠补偿再发回来。无需新数据库或事务框架。

1. M02 或 M07 将变更请求放入同一业务写入队列，先查 OperationId。已完成且同意图直接返回原结果，即使当前修订已变化；同 ID 不同意图拒绝。已被回退的行动仍返回原历史结果并标 `Superseded`，不会重施。
2. 对新操作读取最新已提交状态，检查业务条件与相关期望修订；让每个负责者校验并返回候选切片。预览没有修改权，也不占用物品或权益。
3. 组织者检查共同不变量，形成一个候选版本，包含各负责者变化、操作结果、流程阶段及必要历史。某参与方拒绝则整项不变；候选内部计算不能触发 SDK、动画或奖励通知。
4. M12 提交这个完整版本。确认可恢复的持久提交后，客户端一次切换为新版本，再给结果／发显示通知；成功返回前不能只发布其中一份 Model。
5. 保存失败或结果不明期间不接受冲突变更。可以查询、重试同操作或显示原已提交只读状态；不能把未持久的候选展示为到账、已学或已开战。

| 状态 | 调用方处理及保留什么 |
| --- | --- |
| `Completed` | 所有参与变化及结果已在同一可恢复版本，满足H10声明并已验证的故障模型下的成功持久门槛；可显示成功。重复查询返回相同结果。仅文件可见或同进程回读不足以证明该门槛。 |
| `Rejected(reason)` | 条件不满足，如等级／资源不足、非法路线、错误阶段、对象不存在；不扣物、不推进回合、不抽随机、不加历史。修正意图后用新 ID。 |
| `StaleContext` | 对象仍存在但预览／局面／偏好等依据过时；重读并重新确认，不能静默改目标、成本或路线。 |
| `Busy` | 前一项提交／演出门闩尚未满足对应操作条件；不排入一个未来自动执行的攻击。 |
| `SaveFailed` | 已确认该候选未提交；原完整版本仍有效，重试同 ID 和候选，不重复计算随机奖励。 |
| `CommitUnknown` | 不能判定是否已持久；阻止冲突写入，按 CommitId／OperationId 查询持久结果。不能当失败新建 ID 再办。 |
| `PendingExternal / GrantReady` | 广告或在线请求、已获未兑现资格各自是已保存的完整业务状态；不等于复活／增益等效果已经完成。 |
| `UnsupportedBinding / RecoveryBlocked` | 所需规则版本或一致性缺失；保留原资料并停止受影响流程，不默换配置、不清存档重新开局。 |
| `ReconciliationRequired` | 跨档候选存在明确的来源、效果或身份核对缺口；保留两侧资料及原操作并返回具体原因。不是已完成切换，未解决的可用结果必须继续有设计责任人。 |

去重同时使用业务唯一键：首次赠证 `(PlayerId, Level16EntryGift)`、首通 `(PlayerId, LevelId)`、学习 `(CharacterId, SkillId)`、基础结束 `AttemptId`、增益 `SettlementId`、广告事实 `AdFactId`。新 OperationId 不能绕过这些约束。新的合成或用卡确认可重复开展，但必须是新的明确意图，不能由旧 UI 回调生成。

## 3. H02 入场与资料交接

**发起／接收：** M01 选择开放关卡，M02 组织 M05→M03／M04／M10→M06，M07核对奖励初态，M12提供种子材料并保存。目标是教学与资源交接已完成的一个可操作尝试；入场演出只是后续显示门闩。

**输入：** PlayerId、LevelId、普通入场或重来来源、阵容／装配选择、OperationId、相关状态修订及目标发布绑定。进度返回 `EntryAllowed` 或具体 `TeachingRequired / Locked / NoReadyMember`，包含缺口、未完成步骤和允许返回位置。推荐等级不是禁入门槛。

**成功流程：**

1. M05 找到或建立该关的未完成 ChallengeId；教学阶段也可已有挑战。完成必要 H03 后重新读取当前资料，不能使用进入弹层之前的成长缓存。16 未满足学习和用途说明只拦该 Boss 开战，不拦地图、队伍或旧关。
2. M03 产出一次已计算基础属性的 EntryData。阵容最多三人；恢复中的选中角色保留槽位和恢复显示，但不列为本次可出战参与者；至少一人可出战。空槽不自动补人。战斗过程中局外升级不追写入场属性。
3. M04 按已选物品／职业适配、现有量及每槽一叠上限 99，产生携带和冻结方案；库存不足则按实有量，零库存仍保留选择并允许入场。预览不冻结，教学未结束不冻结。
4. M06 用完整资料创建新 AttemptId 的候选局面，检查定义引用、每面对敌人与配对映射及随机契约；按第18节封存战斗／掉落／增益三域初态，M07核对奖励输入，不提前发奖。应用流程将创建结果、冻结记录、挑战关系和流程阶段一起提交。只有持久完成后才宣布开战及开始业务抽样。

**库存不变量：** 对每种物品定义 `T=长期总拥有量`，`L=局外已分配量`，`R=活动尝试冻结量`，`F=T−L−R≥0`。T 已包含 L 与 R，不能显示或发奖时再相加。入场将对应 L 转为 R，并用 F 补足，故 T 不变；本局携带 C 就是该次 R，余量 U 由 M06 维护，`0≤U≤C`。同一件物品不能同时计入 L 和 R；合成／其他支出只能使用未冻结且未分配的量，转出局外分配必须另作明确装配变化。战内不自动补充。

物品公式固定：入场 C、终局余量 U，真实用量 `D=C−U`。胜利 `T'=T−D+本次物品奖励`，解除 R 并把 U 归为该槽局外分配；失败／退出 `T'=T`，解除 R 并归回 C。这里的“返还”是恢复可用／装配状态，不能再次给 T 加 D。随后入场再按现有库存补叠。回退过的消耗不计 D；救援既不扣长期账，也不解冻。

普通经验先按绑定版本计算 `floor(基础经验×该角色等级修正×该角色评分倍率)`；广告通关取基础经验。M07 计算应得向量，M03 仅按向量累加经验并处理跨级，不能再套评分。8 通关后成长获得法师，9 首次可用；21／37 职业节点按配置。16 的首通第二证由首通唯一键控制，与战前首证无关；旧关只给重打奖励。

**封闭贡献报告：** M06给原尝试／绑定／参与者及每次原攻击或DOT批、效果来源、目标、受益者、种类和精确实际量；同源AOE各目标是不同事实，完全重复的同目标效果段拒绝。受击应保留格挡、盾、实际HP和溢出四段，溢出无贡献。M07沿绑定试调权重，只有同次攻击且同受益者的嘲讽与HP承伤分取max，不跨攻击合并；能力明确未启用与来源缺失分开。沿[评分交接](details/contribution-scoring.md)求固定基础奖励，H08仍依原BaseReward，M03只应用整数向量。N2-I1的80组固定入场对照已接收，不等同全事件模型或新成长；完整火球回放不是定义这些字段和规则的前置。

**重复／冲突：** AttemptId 若已有结束记录，同意图返回原结果；再提交相反结果返回 `AttemptAlreadyClosed`，不能先退物后又按胜利扣一次。正常胜利与晚到广告同时竞争，以写入队列和当前尝试状态裁定，最多一个基础结果。M07 不因重新打开结算页面重算随机掉落或发首通奖励。

**中断／完成：** 正常战斗的 `WonPendingSettlement` 是已完成战斗操作、尚未完成永久结算的可恢复阶段；H10 必须先续办 H06，不能又让玩家攻击或另开尝试。广告通关没有单独持久的“资格已用但尚未结算”阶段：联合提交前仍为原活动局面及未用资格，提交后为整个已完成结果。各负责者变化、封闭记录、奖励依据及流程去向同代际完成后才显示到账并允许下一关。保存前中断无部分入账，保存后回执丢失按结果查询。A02、A04、A05、A09。

正常解锁法师时，已批准保留的独有广告固定经验按扩展第4节由M03独立应用；法师仍先按B的正常解锁配置初始化，不追补本关参战经验。该固定增量不进入本次BaseReward，也不被H08再次倍增；待入账／已应用及来源依据随H10一起保存。

**原第8关广告结果接入：** 用户已定A广告通关8、所选B尚未开放8时，原经验／掉落／通关及法师／后续开放整体保留，等B正常开放8后一次接入，无需重打。M07在S09区分源结算已完成与目标Deferred／Applied，后者不是WonPendingSettlement，不阻断B正常完成前置。M05给B正常开放证明，M03／M04／M05提供各自候选，M02联合H10；不制造B新战斗／Settlement或新的广告资格。打开8的正常结算与原8结果分别记账，前者BaseReward及其H08不包含后者；完整限定交接只在扩展第7节定义。

## 10. H08 结算后的可选广告增益

**发起／接收：** 基础 SettlementId 已 Completed，玩家主动选择 M07 保存的增益报价，经 M08／M12 广告取得资格；M07 联合 M03／M04／M08 提交。未选择广告不影响基础奖励，也不阻止下一关；广告直接通关与此广告必须分别选择。

**输入／输出：** 固定 BaseReward、SettlementId、BonusId、广告 UseId、绑定的增益规则和一次倍率结果。M07 用与战斗随机流分离、已绑定报价的随机依据确定五档倍率一次；重试与崩溃恢复不重抽。轮盘播放只展示结果，不由停针动画决定倍率。当前试调档位为 2.0／2.2／2.5／2.8／3.0，概率 35／25／20／15／5，定义更新不改变旧报价。

对原基础向量 B 计算增量：

- 角色经验总额 `floor(B经验×倍率)`，追加额为该值减已发 B经验。
- 每种经验卡／普通材料先以基础结算内同类合并量计算 `ceil(B数量×倍率)`，追加额为该值减已发 B数量。
- 职业之证、职业解锁和其他未在参与范围内的项目追加为 0；不重写首通，不再次放行基础掉落。

例如原经验14、倍率2.2，总30、追加16；原同类材料2，总5、追加3。绝不是基础已发后再发30和5，也不是拿已增长奖励再乘。角色后来升级，仍追加原固定经验，M03 只处理新增经验的升级；不重算旧关评分或等级衰减。

**完成／失败／重复：** 原固定追加向量及准确Grant／Use先按H14成为远端ResultCommitted，再将增量、BonusId完成及使用投影同次本机持久提交；同SettlementId不能产生第二份增益。Prepared、远端承诺、本机到账分别可查询，未知不重抽；广告失败无增量，已承诺但本机失败续办同一结果，不能释放资格另发。迟到仍作用原角色／原结算，不修改新战斗入场属性；目标不兼容返回具体核对缺口。H10查询安装结果，不因重开页面重做基础奖励。A05、A06。

## 12. H10 保存、加载与流程恢复

**发起／接收：** M02／M07 及状态负责者依第 2 节形成完整候选，M12 负责持久交付；加载由 M02 组织各负责者校验。建议保存整个业务一致版本，包括永久资料、活动尝试和历史、冻结、挑战、广告事实／使用、结束／增益记录与稳定操作结果；不保存动画进度作为业务依据。S15在玩家档中只存包／整关绑定，不复制发布包正文；S16制作草稿和发布验证证据属于M11工作区，不进入玩家业务提交。S14已保存攻略及其适用依据仍须保存。

**本机保存与跨设备范围不同：** 上述完整版本用于本机持久化及恢复。用户明确不跨设备同步进行中战斗和本局撤销历史；不能直接把此版本当云同步负载，也不能仅删去活动战斗字段后留下冻结／使用引用。H13采用无活动尝试且基础结算完成的局外检查点，另标必要结算／权益凭据及其效果是否已包含；远端条件提交与本机完整安装分开恢复。详见[H13](runtime-extension-contracts.md#5-h13-局外检查点选档与本机安装)；本机恢复同一活动尝试的要求不变。用户补充“战斗如果不能同步，那就放弃同步”：新设备从已同步局外状态继续，原设备有本机档时可续局；设备及本机档丢失不恢复该战斗。该决定不取消局外同步或广告保护，不为未决Use提供已用／可再用的证明。

固定奖励另保存所采用协议、RewardResultId及远端承诺／本机安装阶段；M12不替业务重复施加固定向量。首次／迟到本机到账按当前CommitId核对来源收讫／后继索引并H10提交，活动战斗中也可增加永久资料但不改入场属性；不要求或伪造新的局外检查点。到合法局外边界才形成InclusionEvidence，跨档导入另按H13联合核对。远端首次奖励不覆盖未上传后继消费的丢失风险；旧许可未决不能当新协议Prepared自动取消。

**跨档广告保护范围已确认：** 普通分歧由玩家选一份；广告直接奖励及其已经转化的结果独立保留，广告帮助取得的后续普通闯关记录和奖励不因此合并。例：未选A含广告3张卡、已用2张给战士、余1张；选择完全不含该来源的B时，保留B普通进度，并接入A对应经验和1张卡，不重发原3张卡、不覆盖整份A角色资料。目标档已包含的同一来源结果不重复入账，重试也不再次增加收益。[用户确认及交接](session-plan.md#16-用户决定跨档保护广告直接奖励及已转化结果)

**同源分歧消费已确认：** 同一张已经发入背包的广告卡同步到A／B，两端离线分别用于战士／法师，玩家选A时只保留A中的一种结果；另一侧真正独立广告所得仍按上一条保护。此决定不扩大为整个多张Grant必须一起选，也不令每次用卡必须联网。[用户原答及界限](session-plan.md#17-用户决定同一张广告卡的分歧消费只保留所选结果)

保护凭据须能让M03／M04／M07／M08核对原发放、来源分摊、实际转化、受益对象及目标档已包含或已继续消耗的部分；余额耗尽仍留必要防重证据，仅Fact或used标记不足。M02组织各负责者应用经核对的候选，保存与中断恢复仍按H10；SourceSlice、EffectReceipt和InclusionEvidence只在[扩展第2、7节](runtime-extension-contracts.md#7-广告来源及跨档核对)定义。用户已确认未过8的B所缺法师的独有广告固定经验保留至正常解锁后入账，具体候选／完成语义见扩展第4节；待入账状态不显示成已加经验。混合合成、其他角色身份及分用途保护仍有明确未决，不擅自补偿。

保存必须提供可查询CommitId，并区分两个保证：未决提交因进程中断时恢复旧完整版本或新完整版本；已返回Completed的操作，在所支持的故障模型内重启／掉电后必须保留该次或更晚已提交版本，不能仅因旧版完整就丢掉成功操作。文件及目录同步、真实路径／文件系统和设备遵守同步语义是后一保证的前置；本轮均未验证。损坏、卸载／清数据、人工回滚、系统恢复旧备份或硬件不遵守同步语义不在此保证内；本地协议也不能检测全部新证据一起消失。能力未验证不能默降Completed含义；能力不足应阻塞正式保存或由SD00明确修订范围。

物理推荐与故障矩阵详见[SD02](details/platform-save.md)：不可变完整代际加提交封记，保留当前／前一物理代；这是待实现验证的方案。不能让各Model独立异步写文件后把最后一个回调当全局完成。自动存储快照只采已提交版本；每动作全写完整活动历史的空间与写入增长必须测量，不能用暗加回合上限或删除可回退历史解决。

**回退与保存区别：** 战斗撤销生成新的完整保存代际，只有 M06 战斗内容及指定 M08 使用状态回退；最新永久状态／广告事实／偏好一起保留。恢复整份旧存档不属于正常战斗撤销。备份兼容和损坏恢复不能承诺找回从未持久记录的外部事实。A03、A05、A09、A10。

## 13. 配置、数值与随机的共同约束

**同版本比较条件：** 内容指纹及Rule／Numeric／Random身份一致只是前置，还必须同入场资料、局面、ActionConditions、完整随机流及PRD，并具有该执行产物通过对应固定样例的能力证据。M10交付版本描述和样例身份，M03／M06／M07分别给成长、战斗、奖励结果；M09／M11比较同一顺序结果和新状态，不能另写一套规则。未知计算版本返回UnsupportedBinding；样例不一致不得发布／启用，不用UI舍入或epsilon临时“对齐”。

SD06牵头的计算契约须明确表示范围、溢出、每个运算的舍入位置、评分log₂与PRD触发顺序，SD03／SD08共同核对。固定边界样例至少含：`13.9999999995`直接floor=13与加epsilon得14的差异；`2.0000000005`直接ceil=3与减epsilon得2的差异；W4基础124／23.6；G01经验14；最大HP19、缺2的上弦现已裁定恢复1.9，受实际缺血限制、仅正恢复耗次数。前两项及19HP是技术合成输入；上弦普通模型迁移及合法12关3.2见[主策划I／J](../../game-design/2026-09-15-content-planning-sync-reply.md)。火球仍成对候选，不能因表示选择而定案；上弦与有限评分区间证据不代表完整Numeric／Random规范已经完成。

已定DOT贡献向量另含H=5、d=(4,6)→c=(2,3)，H=1、d=(1,2)→c=(1/3,2/3)，交换来源排列仍逐来源相同。非整数贡献须精确保留，不能逐项floor或加epsilon；整数经验和库存的出口约束不能外推为贡献必须整数。精确表示／资源上界仍由Numeric设计证明，不以机器范围给真实贡献新增玩法上限。

内容离线校准可先使用显式有限被动触发分支表做成对条件回放，并标“PRD可达性未证明”；这不是关闭正式被动，也不保证任意长无触发序列合法。升格为正式合法随机见证时再补完整随机初态／PRD及触发消耗证明。该分层允许已明确效果与输入继续校准，不削弱本节正式同版本比较及发布门槛。

一场尝试绑定所有未来面的定义；保存和历史保留此绑定。客户端、攻略、内容见证只有使用相同计算契约，才可比较结果。随机输入必须包含算法版本、完整流状态／位置及每角色每被动的 PRD 积累；只保存 seed 而丢失抽取位置不足。抽取触发点与顺序属于战斗详细设计的对外确定性约束，需形成固定样例供各消费者复用。

M10首版不自动裁剪已发布包；未来回收必须核对当前玩家档、保留物理备份代、CommitUnknown候选及未结业务等全部引用根。包的五字段ContentBinding与整关扩展均保留原值；不仅原数据要在，对应Rule／Numeric／Random执行能力也必须支持。缺失时停止受影响恢复，不自动热换新包或降级旧业务存档。

新普通入场初始化；死亡、复活及翻面不重置 PRD；回退恢复；立即重来恢复原入场初态。无效操作、预览、演出、未发生的尸体追加伤害不得推进随机；物品普通装配不直接清固有积累。基础掉落、结算倍率使用与战斗分开的随机依据，避免先看广告改变下一次暴击。

基础掉落与增益倍率的抽取输入必须在首次抽取前已持久：第18节选定入场保存三域初态，基础结算再保存增益报价及其原随机依据，并关联稳定AttemptId／SettlementId和绑定。不能只把新抽结果放入尚未持久的候选；保存失败、进程中断和新OperationId均不能重抽同一业务结果。未成入场候选丢失与已成依据恢复分别按SC01处理，具体实现仍须验证。

配置须能区分基础成长公式／表与已计算入场属性，战斗不重复套算。整数经验、库存、分数和生命计算遵守对应版本精度与舍入；材料／卡增益 ceil、经验增益 floor 的规定不能由各调用方自定。火球两组倍率保持候选，发布前由策划／配表审定。默认攻略的随机前提必须显式；固定种子见证不宣称所有随机情形必胜。

NC01的数学值及评分整数出口现按第15节统一；它关闭“非整数贡献是否量化、评分恰在整数边界怎样结束”的共同语义缺口。RC01状态／采样及机会边界见第16节；实际表示、运行工作量和完整Random仍须后续证据，不能把其余缺口反写成已定语义仍待选。

## 15. NC01 精确输入与评分取整出口

### 值、职责与完成对象

当前十进制常数和整数比按其精确值进入运算。统一比较值为约分整数比n/d，d>0、gcd(|n|,d)=1，零为0/1；例如0.08=2/25、1.9=19/10。此为逻辑值的唯一表示，不要求玩家档存成两个字符串，也不指定整数库／位宽。不得先转二进制float再声称还原了原十进制。

加、减、乘、除和比较按数学整数／有理数定义；除数0必须拒绝，比较可用精确交叉乘积。业务字段的非负／整数域由原定义检查；允许内部差值为负不等于允许负HP或负奖励。约分不损失精度，有限机器乘积不得回绕、饱和或靠epsilon继续；空间／时间不足走下述明确缺口。

### 评分出口、边界与终止证明

限定已绑定公式为F=E×G×(a+b×log₂x)，x=1+C/J；E为非负整数，C为精确非负贡献，J为正有理参考，G、a、b为非负有理值。现行a=b=1/2及原等级公式由绑定提供，不写成可任意替换玩家规则的参数入口。先校验完整输入，即使E=0也不能接受缺J／来源的报告。

令A=E×G×a、B=E×G×b，则F=A+B×log₂x且x≥1。B=0时直接对有理A求floor；x为精确2的整数幂时精确得到k=log₂x，对A+B×k求floor。幂判定必须是整数比精确判定，不用float或近似log猜k。

其余输入按x=2^k y、1≤y<2精确归一，k为整数。可采用[数值研究§5](../2026-09-17/numeric-random-research.md#5-log₂-的最少确定方向)已提出的有理区间路线；规范结果是准确floor，具体执行实现可有不同内部优化，但必须证明同一结果及其资源能力。

主源公式ln y=2Σ(t^(2j+1)/(2j+1))，t=(y−1)/(y+1)，来自[NIST DLMF 4.6.4](https://dlmf.nist.gov/4.6.E4)，2026-09-19复核。本节以下尾界及终止论证是SD00的数学推导，不冒称NIST给出了本游戏算法或设备保证。

取N≥1项，L(y,N)=2Σ(j=0…N−1)t^(2j+1)/(2j+1)，U(y,N)=L+2t^(2N+1)/((2N+1)(1−t²))。尾部每个分母≥2N+1，故用几何级数得到0≤尾项≤该余量；全部界为有理数。对ln2取t=1/3得到L₂>0、U₂，对ln y得到Lᵧ、Uᵧ，则log₂x在[k+Lᵧ/U₂,k+Uᵧ/L₂]内。

将此区间整体代入A+B×log₂x，只有最终下界／上界floor相同才返回该整数；区间宽<1本身不足，因为仍可能跨整数。跨界则精化，资源不足则明确不产生候选；不取中点、不加epsilon、不按现有12项样本设置通用通过阈值。

**逐输入终止：** 对正有理x，若log₂x=p/q为最简有理数，则x^q=2^p。将x写成互素整数比，唯一质因数分解迫使x只能是2的整数幂（本域x≥1）；因此非幂x的log₂x为无理数。B>0且A、B有理时，F不可能为整数。上述有理上下界随N增加收敛到F；每个固定输入与相邻整数间均有正距离，所以必有有限N使两个floor相同。B=0和精确幂已走精确分支，不会在整数边界无限精化。

这证明当前数学输入域的**每个固定输入**有有限结果，不证明全部输入共用有限N、固定位宽或手机可接受耗时。不能据此批准任意循环预算或无界分母分配；后续须测量并验证实际执行范围。这里没有运行区间器，也没有重跑240个既有样本。

### 固定主源、转换与完整状态

2026-09-19实读PCG原仓库修订`bc39cd76ac3d541e618606bcc6e1e5ba5e5e6aa3`的[转换／初始化源码](https://raw.githubusercontent.com/imneme/pcg-c-basic/bc39cd76ac3d541e618606bcc6e1e5ba5e5e6aa3/pcg_basic.c)和[状态声明](https://raw.githubusercontent.com/imneme/pcg-c-basic/bc39cd76ac3d541e618606bcc6e1e5ba5e5e6aa3/pcg_basic.h)。以下固定该算法的数学转换；种子输入范围、字节见证、多字采样与业务次序是本项目适配，不归称原作者保证。

状态为无符号64位s和奇数64位inc；一次Next先保存old=s，再令s=(old×6364136223846793005+inc) mod 2^64。令x=(((old右移18) XOR old)右移27) mod 2^32、rot=old右移59；返回32位x右旋rot位，rot=0时原样返回x。全部右移补零；只有此PRNG转换按固定字宽回绕，不能推广到HP、经验或计数器溢出。

初始化接显式a、b，本适配规定0≤a<2^64、0≤b<2^63，超界拒绝。置s=0、inc=2b+1；Next一次，s=(s+a) mod 2^64，再Next一次；这两字丢弃，完成后业务原始字计数w=0。限制b为63位避免原初始化高位被丢弃造成种子别名；不以宿主哈希／当前帧或UI时刻补种子。恢复直接安装合法s／inc，不再次初始化。

### 精确概率与原始字消耗

对约分有理概率q=a/b，先校验b>0及0≤a≤b。q=0返回不触发、q=1返回触发，均消耗0个原始字；这两个确定结果仍是已发生的合法机会，其业务结果／PRD更新不能因为未调用Next而跳过。无合法机会则连机会本身也不存在。

0<q<1时先取U∈[0,b)，以U<a为触发。通用整数采样对n>1取最小k≥1使n≤2^(32k)，令M=2^(32k)、t=M mod n；顺次取k个32位原始字，第一字为最高位，拼成R。R<t则整组丢弃重取k字，否则返回R mod n。n=1直接返回0、耗字0；n≤0或非整数拒绝。n=2^32使用一字、阈值0，不把n转成溢出的32位0。

每次Next都增加w，包括拒绝组；不得只记录成功抽样次数。拼接、n、t和比较使用第15节精确整数语义，不限制概率分母必须装入一个机器字，也不先用floor(q×2^64)量化。资源不足可拒绝能力，不能暗改分母、概率或候选结果。

映射论证：接收区间[t,M)长度是n的整数倍，各余数原像数相同；在原始字组均匀且各次重取独立的模型下，接受结果均匀，故触发率为a/b。这只证明适配不添加取模／阈值量化偏差，不证明有限PCG字组独立均匀或任意固定种子都在有限预算内完成；超过原生一字的拼接亦是本项目待验证适配。

预算是原始字／运算工作量能力，不是“重试几次后当未触发”。用完预算、空间不足或中途报错时整个业务候选不发布，前态不变；同输入可用更大获准预算重算同一前缀，不能跳过拒绝字、换种子或先提交局部PRD。保存未知时优先查H10原操作，不以重算替代提交查证。

### PRD参数与确定的机会次序

对已有主动使用的PRD定义，本包适配0<C≤1且f为非负整数，q=min(1,(f+1)C)。一次合法机会成功后f=0，失败后f增加1；新入场各f=0。概率已到1时不再抽字但必须成功复位。未启用／无能力的分支不造机会，原f保持；缺C不是概率0。此域不增加新的零概率被动或临时战内概率变更规则。

目标率p与本次q分开：20%档现有C展示为0.0557040429，另列求参值0.05570404294978187，来自[prd.csv](../../game-design/balance/results/prd.csv)及[calibrate.py](../../game-design/balance/calibrate.py)。二者不同，RC01都不自动审定为运行C，也不把每次q改成20%。内容侧可继续校准；冻结时交精确C文本／整数比、目标率、求参／误差依据和参数修订，审前缀机会、长期期望及必出序号，运行方不各自重新二分求C。

f从0开始，固定C下最迟第ceil(1/C)次连续合法机会必出，故完成边界0≤f<ceil(1/C)；这是q公式的数学边界。死亡／控制取消的攻击、闪避后被跳过的命中类被动不累加f，双射首发闪避另见R04。原档f必须可由该绑定解释，发现不合法状态不能截断成最大合法值或改C“修复”。目标率最终调好及随机运行见证均不阻已定效果条件回放。

### 给定C的有限精确证据

在0<C≤1、从f=0开始、每次成功复位且机会条件不变的理想概率模型中，令N=ceil(1/C)，第i次连续未成功后的机会率为qᵢ=min(1,iC)，i从1起。令S₀=1，Sⱼ=∏(i=1…j)(1−qᵢ)，则Sⱼ是前j次全失败的概率；S_N=0。一次等待的期望E(C)=Σ(j=0…N−1)Sⱼ，沿原模型定义长期率ρ(C)=1/E(C)。C有理时上述有限乘积／和／率均精确有理，不需1e−15尾部截断。

此公式给出可审阅的解析证据，不保证任何手机在固定预算完成求参。N或分母增长超出获准离线工作能力时明确未完成；不能提前截掉存活质量、取float近似后称精确，或把C截大来缩短必出序号。运行时只使用已冻结C，求参工作不挪进玩家行动。

ρ在(0,1]连续严格递增：C增大时各Sⱼ不增，S₁=1−C严格减小，因此E严格减小；在任意正C邻域可用有限统一项数和连续截断因子表示。C趋近0时任意固定数量的Sⱼ均趋近1，E无界增大，故ρ趋近0；ρ(1)=1。于是每个0<p≤1有唯一目标根C*；又因qᵢ≥C，E(C)≤1/C，故C*≤p。此处是数学推导，不是运行测试结论。

可用[0,p]作有理二分的初始根区间，0端点只记极限率0，不实际求N或除0。每个正有理中点用有限公式精确比较ρ与p后保留包住根的一半；碰到精确相等可结束。每次参数交付保留ρ(L)≤p≤ρ(U)的依据，L=0时显式标极限端点；区间不能只凭迭代了60次判通过。

冻结的C必须是RC01可接的精确有理参数，满足已审定的|ρ(C)−p|≤ε并落在报告根区间内；ε须为内容明确的非负有理容差。正ε时连续性保证可通过充分精化找到满足容差的有理候选，但不保证固定预算足够。ε=0则只有精确相等才能通过；不能承诺所有目标都有有理精确根，也不能把“很近”记为0误差。

反例：合成目标p=3/5的唯一根为C*=1−1/√3，位于(1/3,1/2)，N=3；E=3−4C+2C²=5/3。根为无理数，任何有限十进制C都不可能严格等于它。因此“数学目标p”和“精确执行参数C的实际模型率ρ”必须分列，是否接受候选误差由原内容校准负责，不能由运行精度默选。这个目标只作证明，不新增职业概率。

### 首次、短关与有限机会

首次率为C，前m次至少成功一次的概率为1−S_m；这两项均不是“前m次平均触发率”。平均率须包含成功复位：D₀(0)=1，其余为0；每一步从每个f分出D(f)×q_f到新f=0，D(f)×(1−q_f)到新f=f+1，各分支相加。累计各步成功质量再除m，m必须为正整数；q_f=min(1,(f+1)C)。各步质量和应保持1，必出分支无失败质量，不以极小数删状态。

短关m数的是该被动真正的机会，不是全队行动次数。R04首箭被闪避仍给双射一次机会，第二箭不另给；战士攻击被闪避则跳过暴击机会。死亡／复活与重来沿原生命周期，不为提升短关均值改成跨关累积。实际战斗的机会数还受攻击／死亡等分支影响，固定m的解析表不等于全章平衡或随机可达性证明。

新普通入场一次请求48字节：按战斗、基础掉落、结算增益预备三个用途各取连续16字节。M12的语义结果是“完整48字节及来源能力身份”或“具体不可用／失败”；来源返回不表示入场已提交，也不保证同OperationId再次请求得到同字节。正常来源必须允许00～ff全部字节值；不足48字节、来源不支持或报错整批拒绝，不补零、不拼旧半批。

每块前8字节按小端解释为a，后8字节按小端解释为t，令b=t mod 2^63，再按§16初始化得(s₀,inc)，业务w=0。这里清最高位仅用于把原始材料映射到规范63位b；直接传入RC01的b≥2^63仍拒绝，恢复的inc／状态也不准截断修复。初始化的两次Next只准备初态，不产生战斗、掉落或倍率结果。

在原始128位块均匀的数学模型下，每个(a,b)有相同的两个原像，因此该映射不偏向某个规范输入；它不证明平台源、PCG字组或三个流的实际统计性质。不同用途的状态实例、计数与业务关联必须独立，数值偶然相等不算错误，不为强求不同而再抽。原始材料仅用于准备；完成记录保留三份初态、用途、绑定、映射身份及原生成入场来源即可，不要求另存一份可修改的48字节权威。

平台来源推荐使用系统支持的密码学随机字节能力。2026-09-19核对[Microsoft RandomNumberGenerator.GetBytes(byte[])官方说明](https://learn.microsoft.com/en-us/dotnet/api/system.security.cryptography.randomnumbergenerator.getbytes?view=net-8.0)：该方法定义填充密码学强随机字节；此处只引用能力语义，不据.NET文档认定Unity 2022.3.18f1／目标后端或渠道已支持。确切Adapter、可调用性和失败证据留平台验证，不新增在线依赖。禁用时钟、帧号、宿主哈希、Unity共享随机或另一个业务流作失败兜底；固定测试材料只能在隔离验证使用。

M09先取得同一完整头对应的输入与资格依据，异步候选及M06共享规则验证均在隔离副本完成，不在后台长持写锁。只有每步合法、覆盖全部剩余面且真正达整关胜利才是ValidatedWin；无解须有覆盖所声明全部合法后续的可检查证明。超时、搜索预算耗尽、候选失败及缺绑定分别返回原分类，不能把“没有找到”改名无解。

### OP-R1：用户已确认的交付准则

**实际答复：** 用户选择“算已交付：同挑战继续免费更新，通关后结束（推荐）”。主稿允许可靠当前无解作为分析结论，本答复进一步确定它的广告服务交付含义；不是把求解超时或候选失败批准为无解。提问与原答见计划第46～47节。

**已定：以有效的当前分析为交付。** 经完整验证的当前获胜步骤或可靠的当前无解结论，内容／依据按上文成功保存，都算已经交付；只收到过时候选或只存原条件的历史不算。无解不是服务立即终止，同一挑战内仍可免费撤销后分析、重来／继续更新，直到通关。用户接受该挑战后来以其他方式通关后，这份已交付资格不再用于同关下次新挑战。

**交付条件共同生效：** 结论类型合格、证明范围完整、当前ContextKey及服务关系仍有效、内容与依据同H10持久完成，缺一项都不能报已交付。此前已交付的内容后来过时、玩家没有照着走或后续解析失败，不返还成一份未交付资格；原服务仍按该Challenge免费更新至通关。未采用“只认获胜步骤”的方案，提问对照只保留作历史依据，不作为另一套运行政策。
