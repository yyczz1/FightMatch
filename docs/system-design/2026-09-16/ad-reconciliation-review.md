# 跨档广告收益与离线消耗：独立契约审查

2026-09-16 起草，2026-09-17 接收最新裁决 · **NEEDS_FIX**（审查完整核对协议的完成性，不否定已冻结边界）· 设计推演；未实现，未运行游戏、测试或云服务。

结论：用户批准的“B从未包含G，补入A中G的2张卡所得经验和1张余卡”以及最新“同一张已领广告卡两端分歧消费，只保留所选档的一种结果”，均可作为确定的验收目标。后者解决了下述单卡反例的产品取舍，不能外推为整个多张Grant共同选档。来源分摊、混合合成及用途兼容仍需具体协议，当前不应宣称任意广告物品消费都能无损核对。

本审查只读仓库入口、项目上下文、[账号研究](../../architecture/2026-09-16/account-sync-research.md)、[会话计划第13～16节](session-plan.md#13-用户目标优先实现跨平台进度互通)、[共同契约H03／H05／H07／H08／H10](interaction-contracts.md)，后按授权补读正式玩法／三组建议／协调回复的广告与材料部分，以及[扩展契约第6～7节](runtime-extension-contracts.md#6-h14-一次广告机会的联网使用与精确撤回)。最新单卡裁决由根会话转达其实际收到的用户原话。6月代码清单是旧记录，不作为当前实现证据。下文100经验等数字仅用于推演，不是配表。

## 1. 已确认边界与最小反例

游客本机先玩后绑定；普通闯关和养成可离线；普通分支由玩家选择一份，未选普通成果不合并；进行中战斗不跨端。尚未兑现的一次广告机会须联网核验，已发进背包的广告物品仍能离线消费。跨档保护广告直接奖励及其已转化结果，后续普通通关不因得到广告帮助而受保护。这些决定不需要重新确认。

**反例一：一次Grant兑现成功，不等于兑现后的物品全局只能消费一次。**

1. G通过联网核验，只兑现一次，发1张100经验卡；此状态同步给A、B。
2. 两端断网；A用该卡给战士+100，B用该卡给法师+100。两次消费各自在本机合法且完成保存，余额都为0。
3. 选A后若保留战士+100及法师+100，1张卡形成200经验；若只保留战士+100，就没有保留B的那个转化结果。

没有发生第二次Grant兑现，故在线Grant排他不处理这个反例。来源身份能识别重复消费，不能令两个不同结果同时可用且不重复价值。保存两侧证据只保全记录，不等于已经保全两个可用结果。即使最终选一份，两端断网期间已经体验过各自效果，不能宣称防止了所有临时重复体验。

**本反例已有用户裁决：** 对同一张已领广告卡同步A／B、离线分别给战士／法师、选择A的准确场景，用户选择“只保留所选存档中的一种结果（推荐）：同一份奖励不因跨设备重复消费而增加价值。”因此最终保留战士+100，不叠加法师+100；不再要求确认这个问题。

**混合合成的条件反例：另一侧独有广告来源，也可能与所选普通成果争用同一投入。**

已核实的首版方向：[正式主稿](../../game-design/2026-09-14-fightmatch-game-design.md)第246～255行明确广告可给经验卡／素材、结算广告增益包含普通材料；第310、344行明确首版固定配方制作职业战术消耗品，永久装备留后续。[三组建议](../../game-design/2026-09-15-three-group-recommendations.md)第137行有“锡片3＋木料1→飞斧6”候选，第138行再次说明广告给常规材料／卡。因此混合来源合成属于已有首版材料合成方向，不应假装只有未来永久装备才会遇到。

以该**候选配方**作条件推演：共同祖先有普通锡片3及木料O=1；A另外获得广告锡片G=3，用G＋O合成6飞斧；B用普通锡片3＋O也合成6飞斧。选B并追加A整批6飞斧，会使同一木料O支持两批产出。G没有重复，也不是Grant许可问题。返还G、换货币、借用B其他同类木料或移除B产出，都不是已授权的技术去重。

该具体配方仍为候选，本审查未核实正式广告报价、正式配表或全部取得路径，不把这个数量见证称为实际游戏已验证可达，也不据此立即追加用户问卷。当前需由内容与库存设计落实实际配方和来源，再证明合法组合，或给出最小具体取舍。不能从“来源独有”直接推出“结果可无损组合”。

## 2. 已批准简单案例所需的最少证据

以下只论证固定卡转固定经验、目标角色可准确对应、规则兼容、没有混合合成或重复消耗的简单范围，不是假称完整算法已得到证明。

| 证据 | 最低要求与用途 |
| --- | --- |
| 原始广告发放 | 稳定的原请求／Fact／Grant／兑现Use和来源资料身份；原报价、物品种类、数量3、规则绑定、已完成发放提交。重传不能造出新来源。 |
| 来源分摊 | 两张确实来自G，而非凭A的总余额倒推；消费操作关联G的数量2、目标CharacterId及同次提交。只追踪受保护来源的批次和数量即可作为简单场景方案，不要求每件普通物品编号。 |
| 固定转化效果 | 稳定效果身份、原固定经验增量200、原目标和规则依据；消费与经验入账在同一业务提交中完成。导入的是该增量，不是A最终等级或整份角色状态。 |
| 该来源的当前终点 | G的3张已成为经验200＋余卡1，原2张不能再恢复。以后余卡继续消费或产物再转化，必须接续相应来源；不能永久重放一个已被后继消费的旧余量。 |
| 所选检查点的包含证明 | 与该检查点／分支及其业务数据一起保存的来源、效果和后继消费依据；能区分完全未含、已含同一结果、已含部分、已转成其他结果、证据不足。账号全局的used不证明B已经收到；库存0也不证明B没收到。 |
| 核对与应用结果 | 稳定选档／核对操作、两侧依据版本、固定候选和结果身份。经验、库存、来源收讫记录及操作结果同次本机提交；确认期间依据变更则重新核对。云端结果未知或本机安装未知均查询原操作。 |

例如B完全不含G，兼容的成长负责者接受固定+200，库存负责者接受G余卡1，二者与收讫证明一次提交。以后重试查原操作；B再用掉余卡后，仍能证明这张曾接入并已消费，不能再补1张。这能解释已批准的具体结果；不能推广为所有来源只做集合并集。

**聚合余额不够。** “卡0、战士等级5、G已用”不能区分G卡已培养战士、普通卡培养战士、G卡已做其他用途或B根本未含G。数量耗尽后也必须保留必要的收讫与消费证据，否则再次同步可把已耗尽来源当缺失奖励重发。原始物品可不在背包，凭据不能因空堆叠被一同删除。

可以使用受保护来源的发放、消费分摊和转化收据，不必把全游戏改为事件溯源。只有当广告来源与普通投入混合时，若要证明普通投入也没有重复，就需要足够识别该次共用投入的证据；不能先声称无需任何普通来源信息，再承诺混合合成条件反例一定可解。证据不足的旧档不能从总量无损还原来源。

## 3. 跨系统边界

| 负责者 | 必须提供／不得越界 |
| --- | --- |
| SD07／M08 | 广告事实、资格、原发放与准确Use／撤回关系；Grant联网许可的未知结果继续用原操作核对。不能把物品后续离线消费当第二次Grant兑现。 |
| SD04／M04 | 发放来源、消费分摊、余量、合成投入和产出关联；混合输出必须报告不可分或冲突，不能自行给普通材料定补偿价。 |
| SD03／M03 | 原固定经验效果、真实角色身份及合法应用结果；等级由合法经验结果计算。不能按职业名把不同角色视为同一个，也不能覆盖整份A角色。 |
| SD08／M07 | 原Settlement／Bonus、固定BaseReward和广告追加量、真实结束方式；不把原基础奖励重新当广告增量。 |
| 同步职责 | 基于两侧检查点和收据提出缺失、已包含、重复或不兼容项；不直接计算成长或替玩家裁决普通分支。 |
| SD11／M02、SD02／M12 | 组织各业务负责者构造一致候选并持久安装、保存操作及证据、按结果恢复；不把上传完成冒充已安装。活动战斗仍按既定安全边界处理。 |

H05的战斗撤回只撤准确的局内Use和效果，不回退永久卡、经验或广告事实。来源核对不得借战斗回退之名把已发永久物品恢复成一份新的广告机会；撤回的是准确Use，Grant本身保留，同一机会再次兑现仍须联网。

## 4. 不能由技术自动替用户决定的边界

| 场景 | 可确定的边界 | 尚不能自动决定 |
| --- | --- | --- |
| 广告卡转经验 | 转固定经验，保留来源和原目标；经验和由它推导的等级不是两个可分别追加的奖励。 | 不兼容经验曲线、等级上限或缺少目标时，是否迁移角色／另选目标／换补偿。H03的超额经验不截断不证明任意版本都兼容。 |
| 广告与普通材料混合合成、用证学习 | 保留完整投入、固定结果和来源关联；技能布尔值不能用“加一次”合并。 | 普通投入能否随不可分产出进入，所选档同一投入已用或技能已学如何处理。原结果与原材料不能双得。 |
| 原广告物品耗尽 | 没有余物不等于未收到；已形成经验／装备等结果追踪其后继，不再恢复原物。 | 短暂效果已经正常消费且没有永久产物时，不能凭“保护”自行发替代收益；来源终止分类须逐用途定义。保留使用记录不是保证在新档还能再用。 |
| 目标角色缺失或身份不同 | 同名／同职业不构成身份相同；可以先做可证明的一一身份映射及兼容检查。 | 创建源角色、把收益转给另一角色、忽略职业或等级条件，都改变玩法，未经授权。待处理不等于该收益已可用。 |
| 广告之后的普通通关 | 普通通关和奖励服从所选普通分支；未选的不补。 | 不能仅凭因果上曾获广告帮助，把后续关卡、掉落或解锁都列入保护。 |
| 复活后靠正常战斗通关 | 复活的Use确实生效；之后的普通通关仍是普通结果。正常使用不恢复已用复活机会；也不传输战斗快照。 | 不能把未选普通胜利转成广告直接通关，也不能因未选该分支给已用复活免费再用。 |
| 广告直接通关 | GrantUse关联实际尝试和结算，不能退化成仅存used；这种结束与普通胜利必须可区分。 | 此用途直接形成的通关标记、基础奖励、首通权益、解锁如何跨档保留，尚无与第16节同样具体的例子。B已首通、前置进度不同或参战角色缺失时不能重发基础奖励或自动跳教学，需专项规则。 |
| H08广告结算增益 | 保护固定追加量及其转化结果；原BaseReward作为计算证据保留，不能再发一次基础向量。 | 若源基础普通通关未选，不能因保存结算依据就把整场普通成果导入；目标／版本不兼容仍须明确处置。 |

“普通通关／广告直接通关／复活后普通通关”应依结算产生方式划分，不能事后仅看曾经看过广告。持久保留原结算证据，不等于把该结算包含的所有普通进度应用到目标档。

## 5. 最少用户取舍与无需再确认的技术工作

**同一张广告卡分歧消费的取舍已确认，不再提问。** 按第1节准确场景，最终跟随玩家所选普通分支保留一种结果，不能把另一侧经验也相加。结合第16节已批准案例，另一侧独有、可证明与所选结果不争用投入的广告来源，其直接收益继续补入。这个取舍保留普通离线消费，但只约束最终接续状态，不能撤销断网期间已经发生的两次体验。

最新单卡回复补足此前第13节普通选档及第16节独有广告来源未覆盖的准确冲突。它没有批准丢弃同一Grant内其他互不冲突的份额；数量批次必须设计可区分的来源份额及包含证明，不能直接把整个Grant当作一张卡。

若首版选择按整个发放G保留所选分支状态，而不核对批内独立份额，也必须明说其粒度：它可能舍弃同一G内本可兼容的另一侧结果，不能冒称只是去掉重复操作。稳定来源分摊有助于以后证明哪些份额互不冲突，但不是已证明的合并算法。

**现在无需再向用户提出已解决的单卡问题；技术设计先继续。** 混合合成与共同普通投入不是单卡裁决自动覆盖的范围，但首版精确内容与合法组合方案应先由设计者落实，不能拿候选飞斧算例冒充已确认的实际矛盾。若实际配方确有无法兼顾的共同投入，再就该案例请求一项必要取舍。角色／规则兼容同样先做可证明的技术映射；只有不能成立且必须改变收益、角色或玩法时才提出具体选择。

不需要新确认即可继续：定义来源与效果身份、固定报价收据、耗尽后的防重证据、检查点包含判定、准确身份映射、候选验证、幂等提交和未知结果恢复；为已批准的简单案例补设计见证。均属现有目标的技术落实。不能无确认引入每次用卡联网、强制单设备、补偿货币、重发原卡或回收所选普通成果。

## 6. 现在可以冻结什么

- **可冻结：** 已确认的离线与联网边界；普通选档与广告保护分开；用户第16节简单案例的目标结果；最新同一张广告卡分歧消费跟随所选档保留一种结果；原价固定、来源可追踪、已含不重复、消耗后不复活原物、精确撤回、同一操作恢复；业务负责者分别计算、一次一致提交。
- **可冻结为交接要求，但还不是已验证能力：** 各系统必须提供第2～3节证据；目标检查点与其权益视图匹配；核对不得只看余额或账号全局used。具体数据粒度、压缩裁剪和兼容迁移仍需设计证明。
- **必须待设计或按实际冲突裁决：** 多份资源的来源分摊粒度及重叠判断；首版混合合成和共同普通投入的组合规则；角色／规则不能兼容时的可用落点；广告直接通关跨档保护的精确业务边界；服务器许可到本机效果及确认之间的完整恢复协议。单卡消费取舍已关闭，不列为待答。

待决时保存两侧资料和操作、阻止把未证实的选档结果标成完成，是必要的故障处理。它没有解决用户最终怎样继续使用这些收益，不能作为完整产品方案或关闭验收的依据。

**扩展契约第6～7节复核：** 已重读根会话修正后的H14，第90行现要求“效果确认未提交”与“原意图已持久终止、旧许可不可续办”同时成立，服务端再核对准确Use后释放；此前仅查一次未提交仍允许迟到旧许可生效的缺口已修正。第95行明确设备丢失时的未确认许可仍待恢复设计，第101行不外推整批Grant，第109～111行承认混合结果待解决；当前这些段落没有把待设计能力冒充完成，也未新增补偿、联网用卡或单设备限制。
