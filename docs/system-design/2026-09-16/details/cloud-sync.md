## 3. 份额、终点和比较顺序

沿用SourceSlice，以`g1=(G,原发放行,单位1)`作展示别名，不是新的主键。G的3张对应g1/g2/g3；J属于不同广告，绝不与G按物品名混合。
用`H(g1)`表示该份额持有，`E1(g1→W,e)`表示已将g1消耗为同源战士W的固定e经验；这是表内简记，实际凭据必须含完整身份／绑定／提交。
批量g1/g2转为2e可共用原收据，但只有原规则明确每单位e且收据逐单位归属可核对时才能拆为两个分析项；不可分结果不能按数量比例切开。
不重算A最终等级、不导入A整份角色、不恢复已消费卡；M03只将被证明缺失的固定增量应用到目标角色，所得等级只计算一次。
一个分支同一份额只有一个有效端点；历史前端点仍留作证据，但不能与后端点同时计入可用物品／经验。两端离线各有合法消费不等于一个分支能有两个端点。

| 比较次序 | 证据成立时的分类和动作 |
| --- | --- |
| 1. 验证完整性与范围 | 身份、绑定、发放数量、输入分摊、消费／经验同提交、索引覆盖及目标合法性不全则Unresolved；不先补发再补证。 |
| 2. 目标完全未接入该来源 | 完整负证据成立才是Absent；对源当前终点提出接入，不重播原整批发放。 |
| 3. 相同端点已含 | 同源份额、相同原效果身份及内容，或同一持有端点已在目标，归SameEffect；保持目标，不按传输次数加量。 |
| 4. 目标含可证明后继 | 目标消费明确沿用先前接入的该端点且提交链可连到接入记录，归DescendantConsumed；旧前端点不能复活。 |
| 5. 已定同卡分歧 | 准确同卡、所选终点为合法消费时归SelectedConsumption（另一侧可持有或消费）；所选仍持卡、另一侧消费则SelectedHolding。只保留所选份额终点，不补另一端经验／原卡或创建延期经验；本包仍要求同源角色及兼容规则。 |
| 6. 其他差异 | 缺准确份额／所选端点证明、不可证明后继且不满足第5项、份额重复或规则／角色不兼容归Unresolved，返回具体缺口；不扩大第5项到混合／不可分产出。 |

第4项必须证明“目标接入→目标消费”的准确链。仅看到源有卡、目标有经验，或仅同Grant，不能把两端真实持有／消费分歧伪装为后继。
分类集合按稳定份额不相交，覆盖本次原发放范围；同一份额不能同时进入Absent和已含集合。相同数值但不同消费收据不能直接当SameEffect。
M04核对每个根的单位总数等于全部唯一端点覆盖量；M03核对本包每单位卡至多贡献一次e。此为定额卡守恒，不给混合材料或其他广告用途设兑换价。
普通经验、普通库存与进度取所选分支原值；只有Absent中合法的原固定端点形成增量。被舍弃消费记录保留为核对证据，关联准确选档裁决与份额，不变成可用经验、延期经验或可重试欠账。
候选检验先查重复／重叠和旧结果，再检查期望版本；已经完成的同意图操作返回原结果。没有任何写操作在比较阶段发生。

## 15. H13的L／R／E、安装与恢复引用

提案P同时固定并核对本机预期CommitId `L`、云端头 `R`、权益证据视图 `E`；E覆盖本次权益判断所依据的M08现行资格／RecoveryDecision／后继Use修订，以及M09交付／关闭覆盖依据的固定引用与可核修订。M08／M09仍各自维护原事实，E不成为第二权威；任一方新证据到达都改变E，即使M08资格修订未变。确认前L／R／E任一变化，都须重新组织并展示，不能把新证据拼入旧确认。

远端阶段使用固定子OperationId，对`R`与完整`E`中的两方固定引用／修订作条件提交并保存原结果／CloudCommitId；不能核这些条件时返回准确能力缺口，不宣称已条件提交。超时查原远端操作；远端Confirmed不等于本机业务Completed。本机阶段使用另一稳定子OperationId，重新核当前`L`及相关`E`，由M02把所选普通状态、M09／M08引用、M16结果及各负责者候选同一H10安装；SaveFailed全旧，CommitUnknown查准确安装OperationId／CommitId。

远端结果已成后若L、E改变或出现活动战斗，保留CloudCommitId和本机最新分支，重新核对；不能把远端事实改失败，也不能回装生成P时的旧整档。查询到旧交付／关闭结果只允许在当前完整头上按原条件恢复内容、依据和历史引用；未重新证明当前ContextKey时不把它标成今日当前攻略，且绝不以可查原结果覆盖后来成长、资格或后继Use。

旧档缺RecoveryDecision、交付引用或后继Use记录不是Absent。M16先取M08当前修订和准确Use链；旧恢复回执、旧“可用”快照或账号“装过”都无权降低修订、再次返还或复开被替代Use。RecoveryDecision先成而旧交付／完整未交付证明晚到时，只补原Use历史：不追回资格、不再释放、不清除或改变后继Use；后继Use日后若独立满足准入，只按自身业务键另核一次。

本文不新增跨设备战斗同步、强制单设备、补偿、恢复次数上限、冷却或重看广告。未证明能力具体为原主体／Player关联的可信认证、跨分支Level／Challenge／Use映射、服务端证据可信与保留期、`R/E`条件提交及多设备排他；这些能力不足时阻受影响的实际办理并返回准确缺口，但不推翻本节已定记录分离、路径分类和恢复引用设计。
