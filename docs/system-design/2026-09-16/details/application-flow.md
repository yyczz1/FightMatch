## 2. M02保存什么、内存暂存什么

| 资料 | 内容与恢复来源 |
| --- | --- |
| S17可恢复办理引用 | 已确认操作及必要父／子关系、原意图／目标引用、所属业务负责者、已完成持久步骤和下一办理位置；与该步业务结果同H10。 |
| 领域状态引用 | 指向M07结算、M08Use／恢复裁定、M03延期、M15绑定、M16选档等原记录；不另存可独立修改的Applied、Grant余额、首通、角色等级或第二云端头。 |
| 当前已发布视图 | M12准确CommitId／代际下各切片的不可变读取入口及相关修订、M14运行集合；只是同一完整头的视图，不成为第二存档权威。 |
| 当前提交槽 | 正在验证／保存的一个候选、expectedHead、原OperationId／指纹、M12 ticket及提交状态；持久事实由M12原结果和负责者记录恢复，不靠内存槽证明成功。 |
| 临时消息与演出门闩 | 带原对象的回调消息、当前有效Attempt／SceneRevision／OperationId令牌；进程丢失后可重建，不把队列内容和动画进度作为已完成业务。 |

S17只记录需要跨中断继续的办理步骤；普通查询、预览、页面切换和每次调用不都建立持久父事务。
同一个领域完成状态只从其负责者读取。恢复时S17引用与领域结果不一致，先依据原操作／完整提交核对，不能选一个较方便的状态继续。
消息已进入内存队列仅代表收到，不承诺中断后仍可取得。不可补取回执的风险由M12接入能力如实返回，不伪造成功、失败或再次观看。
加载前没有可写Model。完整候选也不是公开Model；即使UI能画出结果预览，也不能用它生成后续战斗输入。

| 语义入口 | 必需输入 | 返回与边界 |
| --- | --- | --- |
| 查询视图／原办理 | PlayerId、可选OperationId、请求范围 | 当前可读Commit及可操作范围、原完成对象／阶段／原因；查询不隐式登录、播放广告或兑现待办。 |
| 预览业务意图 | 意图种类、准确对象、绑定、相关当前版本及原负责者输入 | 只读预览和前置缺口；不分配奖励、不冻结物品，不把预览当作用户确认。 |
| 提交明确意图 | PlayerId、稳定OperationId、原语义指纹、目标及相关Commit／State／Scene／Preference修订、原绑定 | 原结果、拒绝／过时／Busy，或当前办理状态；最终玩家Completed必须有H10 CommitId。 |
| 接收领域候选 | 原操作上下文、负责者候选、它们所依据的同一头／修订、完整不变量与引用声明 | 在当前提交槽收齐并复核，不允许M07、领域回调或UI直接调用另一写入通道。 |
| 投递外部回执 | 原请求／阶段操作、用途对象、平台原始回执或远端结果及关联依据 | 只接不可变消息；回到队列后让原负责者核验，不把“当前页面对象”补进旧回执。 |
| 查询／续办本机提交 | PlayerId、准确OperationId和／或CommitId、原意图 | 委托M12 Lookup；已成返回原历史操作结果，业务状态发布只依据M12核验的最新完整头；未知保留写门，明确未成按§5结束或续办。 |
| 请求恢复／重启 | M14 CodeEntered或明确重启意图、运行集合／能力及恢复摘要依据 | 恢复结果及真实可操作范围；CodeEntered、准备完成或重启意图持久不等于BusinessReady。 |
| 报告演出完成 | 原AttemptId、SceneRevision、OperationId及该已提交结果令牌 | 仅匹配当前门闩才移除表现等待；不推进回合、不写奖励，不因旧令牌解开新场输入。 |

原操作记录优先于当前修订：同意图已成即返回原Commit及结果，哪怕等级、场次或页面已经变化；同ID异意图返回OperationConflict。
旧操作已被回退时返回原历史结果与Superseded，不重施；重新行动需要新明确意图，并由M06核当前局面。
未命中操作记录的新ID仍让负责者检查业务键和完整来源终点。首次赠证／学习／首通／基础结算／增益／来源应用不能靠换ID再办。
原完整结果已Applied或有合法后继时，先识别已包含，再检查新接入条件；该结果自身形成的首通／法师不算独立冲突。
ParentOperationId／StepKind只关联已有多持久阶段，如认证→远端关联→本机安装或选档远端→本机安装；不同阶段各用固定子OperationId，不把同ID从申请改为安装。
短期令牌刷新可证明同一原主体，不修改原业务意图；改账号、来源、Use目标或候选不是一次网络重试。

## 4. 单队列的具体处理顺序

队列限定一个PlayerId的全部本机业务写入。M12再独占该玩家物理写入口；发现第二写入者／头分叉交RecoveryBlocked，不在M02合并两份存档。
同步的临界区只覆盖受理、读取当前头、候选核验、提交槽及发布顺序；SDK、网络、下载、动画和用户确认都不持有这段业务锁等待。
动作类请求在门闩未开或阶段不合法时即时返回Busy／领域拒绝，不积压成以后自动攻击、补线、复活或重来。
已保存外部请求的结果可排队回到原办理；它仍须在处理时重验目标和最新事实，消息排在前面不是业务优先权证明。

1. 在队列入口检查恢复／保存写门，读取原操作记录并执行§3防重。只读查询始终不借机创建候选。
2. 对新办理读取一个完整当前头；组合领域所需绑定与版本，M02判断组织阶段，M03～M10等负责者检查自己的真实前置。
3. 预览需要玩家确认时先返回；确认后重新核对。M07结算等已有业务确认来源只沿原封闭报告／持久意图办理，不要求重复问内部顺序。
4. 各负责者从同一当前头产生不可变候选，不发SDK、不改Model、不抽未获持久依据支持的新随机结果。所需固定随机依据由原负责者证明。
5. M02收齐变化切片与未变切片、所有负责者的不变量核对、原绑定／未决恢复根声明、S17必要办理引用及操作结果。无引用的切片也须明确声明。
6. 缺一负责者证明则整项不变；M02只核身份、版本及交叉关系，不接管经验公式、消耗分配、首通判断或角色映射算法。
7. 完整候选交M12 Commit(expectedHead,candidate)。ticket只标识该候选；本机完成未知前不能用下一头构造第二份玩家写入。
8. M12确认H10持久门槛后，M02一次切换完整读取视图和新修订，关闭当前提交槽，再返回完成对象并通知M01展示。
9. 之后才处理排队的旧SDK／远端／偏好消息，读取刚发布的最新状态重验。通知失败不撤销提交；重查原结果重建显示即可。

候选不能在保存线程持有时被后续消息修改。M12只补保存元数据及提交身份，不替候选重算领域结果。
拒绝、StaleContext及SaveFailed均不发布任何候选收益；共同错误的完成对象仍必须明确，不能统一显示成“已取消”。
M07要连续完成两个持久步骤时，前一步发布后才根据新头组织下一步；不把后一步预先计算的整份旧快照覆盖回来。

## 5. 三种等待与未知的隔离

| 等待／失败 | 写入范围与允许操作 | 离开该状态的依据 |
| --- | --- | --- |
| 用户确认或演出 | 查询／页面交互保留；战斗命令依门闩，偏好等独立请求按§7校验。没有候选成功。 | 新明确确认，或匹配已提交结果的演出完成；不靠超时改变业务事实。 |
| 外部PendingExternal／远端Unknown | 网络等待释放全局队列，普通离线业务仍可逐项受理；原Grant／Use、绑定或选档意图冲突由所属领域阻止。 | 原远端操作查询及负责者核验；超时、取消传输或无回执不证明未成。 |
| 本机Commit进行中 | 尚未发布下一头，不接受第二份玩家写入；查询原已提交只读状态及原办理。 | 同ticket的明确H10结果。 |
| 本机SaveFailed | 明确候选未成，保持旧完整头；仍先处理当前候选重试或结束，不暗中用新资料替换它。 | 原意图重试；若改变候选，按下述旧办理结束规则。 |
| 本机CommitUnknown／H13安装Unknown | 尚未证明安全分区，冻结该玩家全部业务写入，包括偏好、到账、自然恢复持久化和另一安装；允许查询／诊断及原Lookup。 | M12证明确切结果并完成必要持久核对；不能通过“只改另一个Model”绕开。 |
| 结构、最新头或必要执行能力恢复失败 | 不发布半份可写资料，保留证据与诊断；不能自动选择旧档或空档。 | 原问题被负责者解决且最新头重新联合校验通过。 |

远端Unknown不是本机CommitUnknown。已保存的网络请求等待回执时，不占用完整快照提交槽；后到结果想写本机时仍受当前H10门控制。
Lookup返回旧O的Completed只证明原操作结果，不回装O快照；仅当O正是M12核验的最新完整头且本机尚未发布它时才发布该头，恢复已取得更晚头则保持更晚头。
领域冲突不等于全局断网锁：同Grant未决不能申请另一Use，同源绑定未决不能抢换账号，旧选档P不能套新L；其他合法离线战斗／养成按各自前置继续。
本机保存未知期间到达回执，只保留可取得的原始依据并请求原服务补取；内存消息可能丢失，不能承诺已保存或启动更多广告。

M12 ConfirmedNotCommitted只证明该候选未提交，不等于原业务许可已失效。特别是NoEffectFinal还需原效果意图已持久终止、旧许可以后不能续办。
保持原候选与原意图时沿原OperationId／ticket重试；当前Commit或前置变化导致必须改候选时，先查清原提交并由M02结束原办理，再形成新的明确操作。
旧办理仍可能提交时不准换ID。需要持久终止的外部阶段，由M08／M15／M16按原协议给候选和证明，M02经H10保存终止；终止U1不能释放U2。
结束办理不删除历史OperationRecord、来源、远端结果或已成收益；取消页面／传输不撤销远端C，也不能删除封记模拟未提交。
物理写失败尚未解除时，不假称终止已经持久。查不到内存缓存、一次文件缺失或旧备份完整均不足以开放写门。

## 6. 从CodeEntered恢复到可操作状态

恢复是一次排他的业务装载过程，不重放所有历史命令。M14运行集合固定，M12玩家最新头唯一；S17残留路由不拥有挑选头的权力。

1. 接收M14 CodeEntered及准确ReleaseSetId／ReleaseCapabilities／摘要依据；暂不实例化可写业务视图或开放战斗按钮。
2. M12 Load取得最新物理完整头、CommitId、代际、完整资料及诊断。未知提交先Lookup，不以旧有效代或缓存界面继续；确无档仍须明确新建意图。
3. 核对加载头／根是否仍在M14授权依据及当前集合能力内；有变化则重核，集合不覆盖则阻断并交M14重启选兼容集合，不在当前进程换半套代码。
4. M10对每个所需完整ContentBinding／DefinitionBinding ResolveExact，取得原指纹和执行能力；不把“当前最新配置”替换到旧尝试、原奖励或延期来源。
5. 各负责者校验各自切片及跨域关系；M02收集完整结果，未全部通过不发布可写Model，也不能先恢复背包让玩家消费。
6. 根据最新领域事实和原操作结果重建S17办理位置与临时视图，丢弃旧动画进度；若恢复须写入，只能经过同一队列／H10，不把读取当兑现。
7. 校验通过后返回准确CommitId、活动对象、待办及逐项可操作范围，M14据此记录BusinessReady；它不表示所有Bonus、延期或网络待办都已完成。

| 负责者交付 | M02联合检查的关联 |
| --- | --- |
| M03／M04 | 学习／卡耗／来源同提交，角色与阵容合法；活动冻结唯一对应Attempt、原C及M06 U关系，当前偏好不从历史覆盖。 |
| M05／M07 | 首通／赠物／职业事件与对应奖励同提交；源Completed与目标延期分开；正常WonPendingSettlement必须有原封闭报告和可续结算依据。 |
| M06／M08 | 真实活动尝试、EntryBaseline、阶段和完整历史；有效Use／撤回／RecoveryDecision对应，已替代Use的旧效果可合法保留为历史。 |
| M15／M16 | 已成关联及原资料来源；固定P、远端C、当前本机L与安装阶段分别可查询，来源／包含证明和所选业务状态同提交。 |
| 全体切片／M12 | OperationRecord、相关修订、当前／待办／未决所需绑定及恢复要求完整，引用互相对应；无字段不当作空集合或无收益。 |

合法Deferred条件未满足不是坏档；不得仅因有待办拒绝BusinessReady。反之，“待办不阻普通获得”不能跳过M14／M10必要恢复根与执行能力检查。
已恢复合法资料中，M03待办映射暂缺只阻该经验应用；若正常职业取得本身配置损坏、必要根不可执行或切片不一致，按真实恢复缺口处理，不擅自划出新安全分区。
无档新建只在明确意图和确认无现存／未决资料后形成初始化候选，经H10完成才可操作。丢失设备不等于允许重建旧战斗或证明旧Use未生效。

## 7. 操作准入与恢复优先矩阵

先处理本机物理未知／恢复校验，再根据本机领域事实处理必须先完成的普通基础结算、到期可接入的原8整包；其余请求按各域前置受理。
下表“允许”均要求恢复通过、无本机H10写门阻断和请求版本有效，不授予UI直接写权限；同一消息可能同时受多行约束。

| 最新事实／办理 | 可操作与组织路由 | 暂缓／拒绝的范围 |
| --- | --- | --- |
| 活动AwaitAction | M06核合法行动；M03／M04处理获准永久操作，M02保持原EntryBaseline；M08许可另办。 | 另一入场、H13整份选档安装及非法装配；不把永久成长追写战斗。 |
| AwaitLinks且仍有活敌 | M06受理免费补线，准确许可可复活倒下者但仍AwaitLinks。 | 普通攻击和跳过待补线；不能因全倒要求先复活才能补线。 |
| AwaitLinks本面清空／最终面清空 | 先免费补线，再由M06翻面或形成WonPendingSettlement，按真实存亡继续。 | 不用过时面许可自动复活；最终全倒补线仍可胜利，不新增免费复活。 |
| AwaitRescue | 查询、免费待办显示、合法单人复活请求或已定退出／重来；广告通关只交原H06／H14负责者。 | 没有可行动者时攻击；等待不返物、不重播敌方阶段，不自行判断通关资格。 |

## 8. 与已接收领域交接的限定实例

教学返回使用[进度稿](progress-tutorial.md)的真实待办：首入16独立赠证完成后，未学／未读说明仍拦16开战；可返回队伍／地图或合法旧关，不清Challenge和原赠证来源。
已有G01固定见证中战士不足时，M03返回缺口；M02组织回刷与返回教学，不自动用卡、借法师证或声明所有养成状态均可恢复。
立即重来交[M06](battle-history.md)和M07按原EntryBaseline、原参战者、原C、随机初态及准确有效Use差集办联合候选；永久成长、偏好、后来广告与真实恢复时间保留。
普通退出与重来不混同；正常退出不自动撤已经有效的复活Use，M02不凭“离开战场”返一次机会，也不由S17恢复整份旧永久资料。

[M08](ad-entitlements.md)给准确许可及当前资格修订，M06核目标／阶段。晚到SDK观看完成可保存原Grant，不能自动复活当前同名角色；过时许可交M08走原意图终止／查询。
RecoveryDecision本机安装只由M08给处置／当前投影候选；M02保持当前战斗及普通进度。原U1已替代后，旧许可不得新生效果，历史已成U1仍可查询。
本机回退旧U1时按M06完整历史和M08准确处置同提交，不返当前U2；新设备无旧档只接合法局外状态，不能构造旧Attempt／NoEffectFinal。

[结算稿](settlement.md)规定原8整包由M07持有；M02保存待办时不另建M03卡Deferred。正常开放先提交，再独立办理整包，失败不回滚打开8的普通奖励。
[成长稿](character-growth.md)规定原卡固定e由M03持有；正常8胜利或获准原8结果接入产生合法职业获得依据时，符合条件的卡e随获得联合应用，另列来源且不进任何BaseReward／H08。与原8同办时卡份额来自另一独立广告Grant，不是已消费的原8掉落q；法师Lv.3只是初始化起点，加e后的合法等级／余量由M03给出。
若卡待办暂不可映射，M03仍可给正常职业获得及保留待办的完整候选；M02不能因“全体候选必须齐全”强迫未获批准的映射或丢掉正常解锁。
后续M03合法独立应用与首次获得不是同一操作；M02先查原结果，再基于当前头办理，不重新创建职业。SD15-R5显式交付后的限定交叉核对记录见§10。

M15关联安装与M16进度安装分别完成；远端关联成功不等于已切档。旧C已成而L更新或进入战斗时，只保存／查询必要原结果，重新核对新提案，不恢复旧L去配C。
固定奖励首次／迟到本机安装和H13整份检查点替换不同：前者合法增量可落当前活动档，后者必须守无活动尝试／基础已成的局外边界。
在线攻略、初次广告通关许可恢复、完整云协议或角色身份算法尚无充分输入时，返回负责者与具体缺口；M02不现场计算补偿或把未经验证结果标Completed。
