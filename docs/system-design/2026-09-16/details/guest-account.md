## 2. 四种身份与信任边界

| 身份／资料 | 归属与最少约束 |
| --- | --- |
| 本机PlayerId | M02创建／恢复的资料来源；角色、物品、请求等业务ID沿用。它不是登录证明，也不因绑定替换成AccountId。 |
| 未绑定广告校验主体 | 尚未绑定正式账号时，服务端核验广告及使用请求所认可的主体；与本机来源有可核验关联。没有使用这些能力的纯本机游客可以没有该主体。 |
| 外部认证主体 | 至少含提供方、应用／租户作用域、该作用域内主体。M12交实际可验证证明，服务端验证；昵称、设备号、头像和客户端上传的主体字符串不足以证明控制权。 |
| AccountId | 游戏服务端账号；由经验证的外部身份映射取得，不要求不同平台使用相同SDK。原PlayerId及已验证的游客主体关联到它，业务来源不重建。 |

纯本机新来源首次接入可以提交本机资料，但仅凭自报PlayerId不能取得已存在服务端来源的资料或广告权益。已有服务端游客主体时必须证明其控制权及与原PlayerId的关联；不能把该字段置空绕过旧归属。

服务端原来源已属其他账号时拒绝本次关联或报告明确归属冲突，不做force-link。同一人能登录两个账号，也不自动授权本包转移认证关联或合并账号。

本包要求M12接入能提供来源控制证明、认证结果关联和原操作查询；证明的取得、更新、保管及丢失恢复是接入验收项，未选择技术载体。无法证明控制权时只阻塞受影响绑定／权益办理，保留原本机普通玩法，不伪造证明或创建替代主体领取旧权益。

短期令牌、秘密和SDK会话由M12接入负责，不进入普通云检查点或由M15复制为业务账号库。S20保存非秘密的原身份、证明引用及服务端确认结果；保存旧关联记录不等于当前会话仍有权读取远端资料。

## 3. 最小记录与不变量

以下为内部记录语义，不要求对应独立C#类、网络端点或新公共ID。

| M15内部记录 | 保存内容与用途 |
| --- | --- |
| 绑定办理 | ParentOperationId、原PlayerId、发起认证上下文、各StepKind及稳定子OperationId、各阶段原输入指纹、已确认目标和结果／待办。目标认证结果追加到对应阶段，不改写已发远端申请的账号或来源。 |
| 关联确认凭据 | 原远端操作、准确PlayerId／游客主体／认证主体作用域／AccountId、服务端确认内容及可查询版本依据。归属确认与进度是否已导入分别记录，不拿CloudCommitId代替关联证明。 |
| 本机关联 | 已安装的原来源→AccountId关系、对应确认凭据及本机安装OperationId／CommitId。原来源名称不改、不拷贝出第二份可独立消费的业务档。 |
| 进度交接待办 | 对应父操作、已安装关联凭据、原PlayerId与目标AccountId、交给M16的办理引用／当前阶段；不在S20另存一份检查点、选档提案或可修改成长。 |

绑定、选档、远端确认、本机安装不是同一个完成对象。M15查询分别返回其实际阶段和依据；只有本机关联的全部候选经H10完成，才回答该安装的Completed；进度完成必须另有M16的H13安装结果。

同一子OperationId绑定一种意图及稳定语义输入，换账号、来源、远端确认或固定候选就是不同意图。网络重新认证取得同一主体的新短期令牌可以用于同一原申请；令牌字节不充当改变业务意图的借口。

同一原来源的未决关联先查询，不能用第二个绑定操作抢跑到另一个账号。已确认同一来源→同一账号的重复请求返回原归属事实及已有待办；新ID不产生第二次导入或重发奖励。关联关系不是可回退的战斗状态。

## 4. 可调用能力与阶段

| 能力 | 输入／输出及调用方责任 |
| --- | --- |
| 查询来源与绑定状态 | 输入PlayerId、父／子操作引用；给本机关联、远端已知阶段、进度交接状态、各完成依据及具体未决。查询不触发登录、选档或发奖。 |
| 准备绑定 | M02收到玩家绑定意图，交原来源、当前关联依据和认证上下文；M15提出S20办理候选。先H10保存父子关系，再允许M12开始外部认证。 |
| 接纳认证结果 | 输入原认证子操作、作用域完整的可验证主体／AccountId及相关性依据；核对原办理后追加结果候选。SDK登录成功不改变PlayerId、当前战斗或普通进度。 |
| 准备／查询远端关联 | 已保存的准确目标、来源及控制证明引用、稳定申请子操作和期望归属依据；服务端返回原操作的Confirmed／Rejected／Unknown及确切对象。M12只传输，M15不自签归属结果。 |
| 提出本机关联安装 | 输入原关联确认及当前完整本机头；M15给S20候选，M02收集相关待办并H10保存。确认不合法、来源变化或已属不同账号时不安装。 |
| 交付进度接入 | 已安装关联、原来源和M16取得的合法局外依据交M16；返回其办理引用及待选档／待安装／核对未决状态。H13的Completed不能由M15自行产生。 |

上表是接入能力要求，不声称SD02已实现认证方法；SD02的Commit／Lookup／完整版本与回调队列语义可直接作为设计输入。M15候选不调用SDK或网络，所有回执先进入M02队列再核验。

| 阶段 | 到达依据 | 可以显示／仍不能显示 |
| --- | --- | --- |
| 本机游客 | 原PlayerId的完整本机资料可恢复 | 可按既定条件离线游玩；不显示账号已绑定。 |
| 认证待办 | 认证意图和子操作已持久，结果未核实 | 正在认证或需继续认证；不改原资料。 |
| 目标已认证 | 原操作的可验证目标已接纳并保存 | 认证目标已确认；不显示原进度已接入。 |
| 远端关联待核对 | 原申请已保存并可能发出，尚无确定结果 | 查询原申请；超时不是已拒绝，也不是已安装。 |
| 远端已关联 | 服务端Confirmed明确来源和账号 | 账号关联已确认、本机待完成；不重建游客。 |
| 本机关联已安装 | 关联凭据、来源关系和交接待办同次H10完成 | 可显示本机关联完成；普通进度仍按M16阶段显示。 |
| 进度处理中／已安装 | M16给H13原办理结果及本机安装CommitId | 处理中不显示切换完成；Completed才显示指定进度已接入。 |

这些阶段名是本文件的展示简称，公共结果仍沿共同契约。认证或服务不可用保持PendingExternal及原因；归属明确拒绝则记录Rejected；身份／业务证明缺口用ReconciliationRequired，不新造一个万能“登录成功”。

## 5. 操作固定、安装与本机变化

一次父办理下，认证、远端关联和本机关联安装分别使用稳定子操作；H13有自己的办理与安装子操作，并记录父关联。父子关系先保存才发请求，旧网络回执只能补充原阶段，不能再次模拟玩家点击绑定。

认证结果接纳前重新核对原办理／来源／目标上下文。已失效或被新上下文取代的结果不切换当前会话；可核验远端事实仍交原操作查询／记录，不能因页面关闭丢掉已成立的关联。与原意图冲突的回执报告OperationConflict，不安装到当前账号。

远端申请只固定身份归属输入，不固定一份以后强行覆盖的本机整档。请求期间普通游玩可以继续，关联结果归队后，M02从**当时最新完整头**构造仅新增S20及必要交接待办的候选；其他业务切片和活动尝试均继承当前头。确认源仍相同且没有冲突关联后，才保存该安装子操作及候选。

本机关联候选一旦交H10，其expectedHead、输入和CommitId按SD02固定；SaveFailed重试同候选，CommitUnknown先Lookup。不能在同一个已固定安装操作内悄换最新整档。需变更候选时，先证明原候选未提交、持久结束原意图，再由组织者重新核对并建立不同子操作；已完成原安装先返回原结果。

这与H13整份选档不同：H13固定两侧检查点、预期本机CommitId／云头／权益视图，任何相关依据变化都重新核对，活动尝试中不得安装远端普通状态。关联成功不会替该提案豁免过时检查。

认证结果尚未被业务接纳并持久、且未发关联申请时，目标账号可能从未确定；恢复原提供方、应用／租户作用域及请求相关性上下文。接入若能查询原认证请求，可核验并保存原结果，不能假设供应商必有此能力。需新认证而无法恢复旧结果时，先经H10持久终止旧认证子意图并建立新子操作，再发起认证；旧结果晚到只记录原意图已结束，不接纳目标或申请关联。此分支不要求证明尚不存在的AccountId记录。

目标主体已经接纳并持久，或关联申请可能已发出时，认证失效仍只允许重新证明**同一已固定主体**后查询／续办原操作，不把刷新凭据变成换账号。无法证明原主体时保留未决及本机资料；不依据“当前SDK登录的是谁”改写已发申请的目标，也不对另一个账号重发同请求。

## 6. H13进度接入及活动尝试

| 条件 | M15交接及M16／M02后续 |
| --- | --- |
| 目标账号无云档 | 交已确认来源关系与M16认可的局外检查点；M16以“目标仍无云档”的条件提交接入，若期间出现云档则转差异核对。不能把先前一次空查询当无条件覆盖授权。 |
| 目标已有云档 | M16读取两侧合法检查点、祖先及同提交权益证据；真实普通分歧由玩家选择。M15只提供归属证明，不按等级高、时间新或卡多代选。 |
| 来源有活动尝试 | 关联及必要广告事实可办理；普通进度只交上一合法局外检查点。本机当前AttemptId、冻结、历史及后续提交保留，选档不能提前覆盖。 |
| 没有可交付的合法检查点 | 交接明确待办原因；M02／M16在合法边界生成，不能通过删战斗字段、解冻或伪结算凑出一个检查点。 |
| 云端接入已成，本机头已变化 | 保留云端结果及本机分支，交M16重新核对；M15的关联仍按已确认事实保留，不回滚账号关系来“撤销上传”。 |

M16返回的进度安装必须经各业务负责者确认及H10，包含来源收讫／后继与原CloudCommitId。M15仅记录对应办理引用和实际结果；转交一次请求或认证通过均不等于奖励可用。

恢复顺序是先核本机未决提交，再查原远端关联／同步操作，最后决定是否需新提案；不是恢复后自动从云端最新档覆盖。网络不可达时，已明确可用的本机普通状态仍按原规则继续，不能将所有离线业务锁在绑定网络等待上。

## 7. 晚到广告与受益对象对应

广告回执始终携原PlayerId、AdRequestId及原用途对象，M08核验后仍使用原Fact／Grant／Use／RewardResultId。M15提供经验证来源→AccountId关系；没有关系时保留在原来源办理，不把新账号或当前页面当发放对象。

绑定发生在广告发起、事实收到或效果安装之间，不生成新的广告资格，也不把已安装奖励重新记作未领。原游客校验主体与账号关联后仍保留必要别名／来源证据供原操作查询，不删旧主体引用后仅靠AccountId去重。

M12丢失回执时是否可补录、服务端是否仍可验证旧主体／原操作，须实际能力验证；身份关联不创造从未收到的广告事实。M08核验成功后才由对应负责者办理，本包不直接追加卡或经验。

| 交接情景 | M15能证明什么 | M03及H13的结果边界 |
| --- | --- | --- |
| 同一来源、共同祖先中相同CharacterId | 原资料归属和保留的来源关联 | M03核角色存在／一一对应及规则后可Mapped；仍须目标来源包含证明，Mapped本身不授权加经验。 |
| 独立游客各创建一个战士 | 只能证明两个资料来源受同账号控制 | 不按ClassId或名称合并；M03可返回AmbiguousIdentity或具体不兼容，相关效果候选未决。 |
| 已定A法师效果、B尚未过8 | 保留原来源及原受益CharacterId，目标尚无角色 | M03返回MissingBeneficiary并按已批准场景给Deferred；不伪造目标CharacterId或提前解锁。H13只可明确报告固定经验已保存待正常解锁。 |
| B后来正常解锁法师 | 原归属依据继续可查询，不生成新奖励身份 | M05证明正常获得，M03建立合法对应并联合应用；规则或映射暂缺保留Deferred，不阻正常解锁，不入BaseReward。 |
| 原身份可对应但旧计算不兼容 | 关联仍然真实，不能改称未绑定 | M03返回IncompatibleRules；身份层不重估卡价、不换角色或发补偿。 |

资料归属、角色对应、来源是否缺失、效果是否应用是四个不同判定。M15无权把MissingBeneficiary一律改成Deferred；独立游客及多次选档的未决仍交SD03／SD15，不因两侧AccountId相同自动通过。

## 8. 断点与恢复表

| 断点／观察 | 保留与恢复动作 | 完成依据／重复行为 |
| --- | --- | --- |
| 认证意图未保存 | 保留原游客；未发外部请求 | 玩家可重新提出绑定，不存在已成功安装。 |
| 认证已开始，目标未接纳持久，且未发关联即中断 | 沿原提供方／作用域上下文恢复；若可查原请求则核验结果，否则需要新认证时先持久终止旧子意图并新建子操作 | 不凭空要求恢复AccountId；旧子操作晚到结果不进入关联，SDK缓存不等于业务目标。 |
| 目标已接纳持久，凭据失效／认证回执丢失 | 重新证明同一已固定主体，查询原关联操作；无法证明则保留未决 | 不走未固定目标的新认证分支，不把已发申请迁给当前SDK账号。 |
| 认证结果已保存，关联尚未发出 | 沿原目标和来源构造／查询申请，不重做进度初始化 | 已存子操作决定是否曾发；不借新账号回调改目标。 |
| 关联申请发出后超时／传输取消 | Unknown，保留原操作和证明引用，联网查询 | 取消传输不撤销远端事实，不新建申请绕过未知。 |
| 远端Confirmed，本机关联保存确定失败 | 原确认和原本机资料保留，沿同安装候选重试 | 远端已成、本机未成分别显示，不重新领取资源或重新建游客。 |
| 本机关联H10结果未知 | 查询安装子操作／CommitId，暂停冲突写入 | 已成返回同一关系和待办；确认未成才续办，未知不换ID。 |
| 本机关联已成，通知丢失 | 从S20及操作结果恢复，继续原M16待办 | 不把再开登录页当第二次导入。 |
