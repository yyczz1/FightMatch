## 1. Module职责与可交付范围

M04唯一维护长期物品数量、局外分配、活动尝试冻结、装配选择／使用偏好及物品来源端点。M03负责经验与技能，M05负责赠证／首通标记，M06负责局内余量U及实际效果，M07负责固定结算奖励，M08负责广告事实和资格，M16只组织来源核对。
M02／M07把各负责者候选送[H10及SD02保存](platform-save.md)；M04不自行持久、不直接加经验、不按动画扣道具、不操作广告SDK。下文Interface与记录是语义设计，不指定C#类型、数据库或资产格式。
验收限定：T/L/R/F守恒、入场与结算守恒、永久支出和收益全有或全无、来源可拆定额卡证明、明确偏好、过时／重复／中断结果。§9列出不能以技术排序代替的玩法决定与后置条件。
已发到背包的广告物品允许离线正常使用；不得为弥补核对缺口新增“每次用卡联网”。跨档切换仍只在合法局外检查点安装，不把本机战斗冻结投影为另一设备可用物品。

## 2. 内部资料与不变量

采用每物品一份数量及来源账、每角色一份装配选择、每活动尝试一份冻结记录；堆叠格子由这些资料派生，不持有独立数量权威。

| 资料 | 最少内容与关系 |
| --- | --- |
| 物品数量 | PlayerId、ItemId、T、StateRevision；T为非负整数，包含已分配L和已冻结R，不另加“已携带数”计算总量。 |
| 局外装配 | CharacterId、职业适配ItemId、分配量L、允许使用的偏好及PreferenceRevision；选择可在L=0时存在。每角色一槽一类、一叠最多99。 |
| 活动冻结 | AttemptId、EntryBaselineId、角色／物品映射、入场C、来源范围映射及原定义绑定；每份数量只属一个L或R。C就是该次R，战内R不随U减少。 |
| 来源账 | 引用公共SourceSlice、原发放／接入、数量覆盖及当前持有／转换端点；受保护来源不得只记Grant总数。普通量可聚合，仅混合转换所需部分保留投入证明。 |
| 消费凭据 | 原OperationId／CommitId、输入份额或必要普通投入、消费前端点、固定用途／产出和EffectReceipt关联、原绑定；已耗尽仍保留防重依据。 |
| 首证用途关联 | Level16EntryGift及原赠物操作／提交、准确物品行／单位端点；与通用证T的对应保留至消费及防重凭据。M05给当前教学用途依据，M04不另存可独立改写的教学完成标记。 |
| 恢复声明 | 本切片格式、当前及未决记录引用的ContentBinding／DefinitionBinding、操作结果与来源根；交M12合入RecoveryRequirements，不另存一份异步版本权威。 |

每物品均满足`F=T−L−R≥0`；对所有装配／冻结求和后再计算F，不从UI可见的一叠推导余额。永久支出以F为数量上界，还须通过该次用途／成本筛选；首证用途限制不记作L或R。要用局外已分配量须先明确改装配，不能暗借L或R。
受保护物品的持有份额合计必须等于其在T中未永久消费的数量；冻结是持有份额上的用途占用，战内暂用不是永久转换终点。凭据历史不计入T，转换后的原份额不得同时算作可用物品。
M06持有`0≤U≤C`及战斗历史；M04只在H06按合法封闭报告应用`D=C−U`，不可在每次攻击先扣T、胜利再扣一次。来源映射必须能由实际D准确定位，不能结算时任意换成另一来源。
冻结记录为每角色／物品保存一个确定的有序份额范围序列，总长C；有效消费占其前D个单位，U对应剩余后缀。M06只推进或随合法回退恢复D/U，M04按同一序列定位结算所耗来源。
顺序必须在入场意图形成时固定，按已批准的来源分配政策选取；同意图重试、翻面、救援和重来不能因背包新奖励改顺序。§9本轮经验卡优先决定不外推战术物品的混合来源，不默认随机挑份额。
若规则将来要求同种物品按不同来源产生不同效果，不能继续只靠数量前缀：须先扩展对应规则／证据，本包不以同名ItemId假定可互换。
多来源同种物品可在一个显示堆叠内；拆叠、合叠、筛选、排序、分页不修改SourceSlice／消费收据。技术压缩只合并身份和端点连续且语义相同的范围，不擦掉份额身份。
数量上下限和乘法溢出按发布计算契约检查；不默默截断、绕回或用UI格式化后的数计算。具体整数表示未在本包另定。

## 3. 对外Interface及候选约束

只提供读取、预览／形成候选、恢复核对三类能力；请求的操作种类承载差异，不把每个内部记账步骤暴露给UI。读取返回不可变值，不允许调用者直接写数量。

| 语义入口 | 输入、输出和必需约束 |
| --- | --- |
| 读取库存与装配 | PlayerId及物品／角色筛选；返回T/L/R/F、装配选择、偏好修订、显示堆叠及来源诊断。活动局内图标数量取M06的U，不能把R误显示为尚可使用C。 |
| 预览永久请求 | 物品支出／合成／装配意图、相关角色依据、ContentBinding、预期状态；返回确定成本、可用量、必要来源分摊和效果摘要。预览不扣物、不冻结、不随机发奖。 |
| 形成变更候选 | 稳定OperationId、原输入指纹、预期CommitId／相关修订、原预览及绑定、参与负责者证明；返回M04完整候选切片、消费／发放凭据和校验结果。只有组织者H10完成才可发布。 |
| 入场／结束候选 | H02携带方案或H06封闭报告，准确Attempt／EntryBaseline、原冻结及定义；返回冻结建立／移交／解除和数量变化。拒绝第二活动尝试、报告不对应或U越界。 |
| 来源与恢复核对 | 准确已提交版本、原发放范围、目标来源覆盖／端点及未决；返回完整性证据、可安装的物品增量或ReconciliationRequired原因。M16不能据返回资料直接改库存。 |

已有同意图操作先返回原结果；同ID异意图拒绝。新请求再检查CommitId、M04修订、相关M03／M05资料和绑定，过时返回StaleContext，不能静默替换卡种、成本、受益者或来源。
未确认的预览采用[SD01当前绑定](configuration.md)；已经持久的固定操作用ResolveExact原绑定。新版本仅已发布／下载不使当前绑定自动变化；教学包与成本包仍须一致。
完成结果带原OperationId、受影响物品／身份、新修订和CommitId；只是形成候选不返回业务Completed。组合中任何负责者拒绝，所有候选均不发布。
M03交付目标、固定经验及按卡单位的数额；M04交付准确成本份额及扣除候选。组织者核对两者输入／绑定完全对应，不能先消费再让M03重新决定给谁。

## 4. 入场、战内与结束的守恒

H02仅对本次实际可出战成员产生携带／冻结；恢复者保留槽位和原局外装配，不纳入本局C，不能让其道具自动挪给另一人。全部不可出战由M03／M05拒绝，M04不借库存绕过。
对每位合法参战者所选物品，从该槽L及F形成至多99的C，先完成所需数量与来源分配，再一次把相应L转R并从F补足；T不变。其他槽的L不被隐式挪用。
例如该角色L2、同类F99，T101：入场C99、L0、R99、F2。它与“换下余2、携带99”的表现一致；无需把两个物理格子的身份当作业务实体。
M04冻结源映射与M06入场C同次H10保存；教学或预览阶段不冻结。新到账同类物品只增加T及F，不能补入已开始战斗的C/U或替换冻结来源。

| 事件 | 输入→候选结果 | 完成／重复依据 |
| --- | --- | --- |
| 入场 | T5、L5、R0、F0→T5、L0、R5、F0；M06 C5/U5 | 新尝试和冻结同提交；回执丢失查原入场，不再冻结5。 |
| 用2、全灭待救援 | M06 U5→3；M04仍T5/R5，不解除或扣长期量 | 行动历史／U同提交；救援复活继续U3，不能先归回5再带入。 |
| 回退用2的行动 | M06恢复相应U及历史状态；T/R不变 | 已撤回实际用量不进入D，偏好仍保留当前值。 |
| 正常／广告胜利 | C5/U3，D2→T3、R0、L3、F0（无本次奖励） | 扣2与结束、奖励、来源消费同次H06/H10；广告跳过后续不虚构消耗。 |
| 失败／主动退出 | C5/U3→T5、R0、L5、F0 | 解除占用，原冻结份额全部仍持有；不能T再加2或5。 |
| 立即重来 | 旧Attempt关闭，新Attempt沿原EntryBaseline；R5从旧尝试移交新尝试，C5/U5 | 同提交只有新尝试持有冻结；不先解冻给外部支出、不按最新T补到99。 |
| 结算另奖4 | 胜利用2且奖4：T'=5−2+4=7、R0、L3、F4 | 原冻结扣除与固定奖励是不同来源行，同次完成；下一次普通入场才补携带。 |

R02原基线重来保留原参战者／槽位、已算属性、HP、规则和随机初态；永久培养／学习与真实恢复时间不回退。本包只移交原C及来源，原未参战者后来恢复也不新增冻结。2026-09-19已核对协调回复H的主策划正式归档签收；本包真实运行验证仍未完成。
同一尝试第一面、翻面、补线、等待救援均维持同一冻结；只有合法H06结束或联合重来能够变更其归属。崩溃恢复原尝试不是重新入场。
若当前T含迟到奖励或局外成长支出，结算按当前完整版本减原D，不用原入场库存快照覆盖当前T。支出仍只能使用F，不影响R可履约。

## 5. 装配、99投影与使用偏好

无活动尝试才允许换槽内物品、调整L及阵容；新装配默认开启，换装与数量转移同次提交。L0保留ItemId选择，允许入场；以后有库存，下次普通入场按实有补充。
显示背包按可呈现范围聚合后拆成99满叠及最多一叠余量；例如自由库存117显示99＋18，角色另有L2时总拥有119，不把119再加2。活动冻结与可支出数量须分别标识，不能把占用量显示成可合成。
自动整理只改变派生排列／UI目录状态，不改变T/L/R、来源分摊或实际效果。背包不设UI格数容量；批量产出仍须满足数量表示及配方条件。
图标点击由M01把当前已提交偏好转换成明确目标`Enabled=true/false`，M02提交原目标及PreferenceRevision；M04候选保存到H10后才显示切换完成，不接收会被重试再次反转的Toggle请求。
同操作重试返回原偏好结果；另一个新意图须依据当前修订，旧回调不能覆盖新偏好。仅改偏好不推进回合、SceneRevision、随机或扣U，但攻略ContextKey按PreferenceRevision失效重验。
允许在战斗中切换使用开关，M06每次合法行动读取已提交ActionConditions并记录；回退只还实际消耗，不把偏好恢复为历史值。关闭仍显示U；U0和关闭通过数量区分，不清装配选择。

## 6. 永久消费、发放与M03交接

H03先由业务负责者确定合法意图和固定效果，再由M04校验成本F及来源；所有输入与结果必须在同一候选被核对。不因为资源充足替玩家自动培养或学习。

| 场景 | M04候选及联合条件 |
| --- | --- |
| 经验卡培养 | M03确定目标等级需k张、每张固定e及超额保留；M04消费k个合法份额，收据逐份额关联原CharacterId和实际ke。M03等级／经验与扣卡一次完成。 |
| 通用证学习 | M03校验等级≥5、职业／技能、未学及玩家确认；所有入口都带M05当前教学依据，M04筛选合法的准确证成本，学习／证耗／教学变化同次提交。已学业务唯一键不能用新OperationId再扣。 |
| 首次16赠证／首通第二证 | M05给两个不同唯一键，M04各加1通用证并关联发放；库存与领取标记同次完成，不按进入UI次数发。 |
| 固定配方制作 | 原RecipeId／绑定、正整数批数b；每种输入合并后消耗b×成本，输出b×产量，检查F及数量范围；扣材料、产出及来源转换同次提交。候选飞斧3＋1→6不在此成为正式配方。 |
| 普通结算／固定广告结果 | M07或原负责者给确定奖励向量；M04仅按原来源核对未包含结果并构造增量，不能另乘广告倍率或重抽。广告ResultCommitted不是本机已到账。 |

M03的固定经验EffectReceipt引用M04同次消费前端点及SourceSlice；M04保存其用途／效果关联而不另存一份可独立增加的角色经验。卡转经验再引起等级增加只算一份效果。
Level16EntryGift发证时，M04把那枚通用证的持有端点与该唯一事件关联，M05领取标记与赠物同H10完成。返回队伍或普通学习菜单不消除此关联；不能通过整理、拆叠或改入口把首证混成任意可花普通量。
教学完成前，M05准确依据限定该枚未消费首证供战士学习嘲讽；M04据学习目标筛成本。法师只能用其他独立合法证，战士合法教学优先用准确首证并与M03学习／M05步骤同次扣除。首证仍是通用ItemId，不冻结整类证；预览显示T/F及本次用途可用量和原因。
先查旧操作结果，不追溯撤销已完成学习；新确认核PlayerId、CommitId、M05／M04修订、适用的原赠物引用及绑定，未领首证也须M05当前完整依据，缺字段不等于无限制。已消费首证保留原凭据而不返还；教学已完且首证尚未消费时，M05完成证明解除用途限制但T不增加。非兼容旧档或缺端点须保全并报告，不自动补证。

| 首证用途见证（数字仅作数量输入） | 候选及完成／中断结果 |
| --- | --- |
| 首证1＋其他证0，法师Lv.6，在普通菜单学习 | T=F=1但此用途合法成本0，拒绝；证与技能不变，返回地图／回刷仍允许。 |
| 首证1＋其他独立合法证1，法师Lv.6学习 | 只取其他证1，法师学习和该证耗同H10；T2→1，首证端点及用途仍保留，不推进战士教学。 |
| 首证保留，回刷后战士W5＋6确认学嘲讽 | 扣准确首证1、M03已学、M05学习步骤同H10；说明另行继续，首证耗后不返还。 |
| 上项保存失败／未知／已成重试 | 明确失败全旧且首证用途不释放；未知查原提交、不新扣；已成返回原学习与证耗，不再次消费。 |

G01指定见证：M5＋92/220、三张50经验卡，M03给k=3、M6＋22，M04给卡3→0；W4＋157/165不变。此后旧关1的W＋14属M07普通奖励，不能把前次法师卡再用于补战士。
独有广告经验跨档接入时，已经消费的卡只导入转换端点，M03应用固定经验或已批准的缺法师待入账记录，M04不再扣目标普通卡也不重发原卡；待入账→已应用由M03维护。
迟到固定发放可以在本机活动战斗按当前CommitId核对后到账；新库存入F、固定经验不改入场属性。跨档整份安装另守H13，不能借迟到发放覆盖活动档。

### 原8整包延期的物品交接
