### 两阶段奖励隔离

记B正常开放8那关的固定W经验为b、该关物品向量为p；原8已固定经验为e、物品向量为q。符号只用于推演，不改配表。
第一提交只按该关BaseReward记b／p及正常开放8；第二提交按原8来源记e／q及8通关／法师／后续事件，不能把b＋e写回第一份BaseReward。
随后玩家合法选择第一关结算的H08时，其经验追加只按该关b计算，物品只按该关合并p计算；不读取当前累计成长或当前库存作倍率基数。
若该W可按倍率m增益，则累计相关经验为b＋e＋floor(b×(m−1))，不是b＋e＋floor((b＋e)×(m−1))；物品按H08原p取整，q不进入其基数。
接入操作不生成原8的新Bonus资格、报价或随机结果；日后原8结算增益的跨档办理不在本包，不默认为可重复领取或自动作废。

## 6. 重复、分支延续与提交恢复

去重同时核对原完整结果、目标分支有效终点、(PlayerId, LevelId=8)首通、(PlayerId, ClassId=法师)职业及每项SourceSlice；新OperationId不能绕过。
不能仅保存“账号已Applied”：源A已结算不代表B已应用；某个历史分支的终点也不能替代当前所选分支的完整包含证明。
M07保存的应用凭据引用M03／M04／M05实际完成项，不另存可独立修改的经验、库存或角色快照；物品消耗后M04只追加准确后继。
当前目标已有Applied及完整后继时，原结果重到只回已包含依据，W不再加e、法师不重建、首通不重发；T为0也不补q。
目标Deferred经H13搬入新的合法所选分支时，保留原结果及前序待办引用，重核新目标进度／包含／映射；新分支终点沿此次选档提交建立，旧分支证据保留。
这次搬入不是制造第二份原奖励：新所选分支只保留一个有效终点；若它已含同一Deferred／Applied则不新增。目标已正常开放时依第5节处理，仍不合并A普通进度。
应用后另选一个不含结果的独立分支、并行来源后继分歧等超出本包证明时，返回具体缺口；不能把历史Applied简单改回Deferred，或自动选择补偿。

## 7. 完整性、引用根与排除边界

M07交付原Use→源Attempt／Settlement→原BaseReward／逐项收据→目标Deferred／Applied的可核对关系；每个引用须能定位原完成依据。
完整性检查覆盖所有经验受益行、全部物品原行与单位范围、全部原一次事件；未列项目必须有原结果为空的证明，不能以摘要散列代替业务覆盖。
M03核对经验行／合法角色映射／应用前后依据；M04核对单位范围、来源终点及数量守恒；M05核对正常开放、合法源结束、首通和职业事件。
M07据各负责者完整核对结果确认整包边界，M16固定所依提交与证据修订；M12只机械验证完整切片／引用声明随同Commit，不解释业务是否真实通关。
散列可发现损坏或同身份异内容，不能独自证明广告真实完成、来源可信或某分支从未包含。缺真实性证明不进入本例成功路径。
原8DefinitionBinding及其规则能力、原结果／来源、目标待办、未决操作／候选及应用后必要防重引用随各切片交RecoveryRequirements；不只声明当前配置。

Applied后即使q已全部消费，原发放、目标应用及后继关系仍保留；物理原A档不必完整复制为玩家档，但所需证明必须可恢复。

## 15. 防重、竞争与恢复顺序

每次请求固定执行：①先查原OperationId／语义指纹；②再查Attempt唯一结束、Settlement／Bonus或来源终点；③仅对真正新办理检查当前Commit／Scene／资格／参与方修订并形成候选。原同意图Completed返回原结果；同ID改方式／对象为OperationConflict；新ID命中同一已Closed终点仍返回已含／`AttemptAlreadyClosed`；若正常H04已成`WonPendingSettlement`但尚未Closed，广告按阶段及既定终局拒绝并只续正常H06。

| 断点／变化 | 保留与续办依据 |
| --- | --- |
| `SaveFailed` | 本机候选明确未成、旧完整头有效；保留原EndIntent、固定BaseReward／随机结果、参与方候选和同一M12 ticket。已经持久的M08申请／远端Use许可仍停在原阶段，不改回Available；同Use续办或由M08按原协议终止／释放，不重算／重抽。 |
| 仅远端Use／Result／确认Unknown | 没有本机CommitUnknown时不占全局提交槽，只在原领域前置允许范围继续：例如基础已成的Bonus等待不阻下一关；广告通关Use未决仍受原Attempt／Use约束。同Grant／Use不能新用、改回Available或换ID。 |
| 本机`CommitUnknown`（含Bonus安装） | 冻结该Player全部业务写入，Lookup原Operation／Commit；不能取消页面后换ID发基础、用资格、装Bonus、解冻或开新Attempt。 |
| Lookup Completed但当前已有更晚头 | 返回原完成对象／Commit及增量0，只从最新完整头展示；不回装旧等级、库存、Attempt或服务快照。 |
| Lookup明确未提交且原上下文仍成立 | 续原固定候选；若当前前置已变，先持久结束原办理，再以新明确操作重核，不能修改原ticket内容。 |
| 永久资料／绑定能力变化 | 已成结果保持原值；未成候选按当前头重核受影响参与方。新等级不重评分，缺旧能力返回UnsupportedBinding，不以新规则修旧结果。 |

原§1～10的第8关Deferred只沿其独立接入Operation办理：它不是普通`WonPendingSettlement`、未结BaseReward或可再抽掉落／Bonus。恢复优先级只在B正常开放8后进入原接入路由；任何普通结束查询都不得把它当本次Attempt收益。
