## 5. 永久丢失恢复的准入与固定输入

| 必须同时核对 | 缺失或相反时 |
| --- | --- |
| 原主体可认证、原来源关联与准确Grant／Use可核验 | 返回具体身份／记录未决；不能用当前同名角色、设备号或重新注册替代。 |
| 玩家明确声明原设备及其本机档永久不可恢复 | 未声明、仅断网、超时、应用重启或可恢复的本机未知提交继续原查询路径，不自动恢复机会。 |
| 被申请的是原局内复活Use，用途及受益身份一致 | 局外恢复、直接通关、资源卡、结算或在线服务不适用此例外。 |
| 原Use效果仍Unresolved，且当前资格待该准确Use确认 | 已知EffectCommitted不适用；已按NoEffectFinal／正常撤回释放者返回现状，不另返一次。 |

声明是用户已批准政策的输入，不是“未产生效果”的证明；离线时长、旧设备标记或找不到文件不能技术证明永久丢失。服务端核验的是主体、记录、声明完整性及当前裁定条件，不能声称能远程删除旧设备缓存。

M16／M12核对原Use的可取得证据；若本机仍有CommitUnknown，先Lookup，不能以本机未知代替永久丢失。跨端已无法取得旧本机档时，不要求构造旧BattleSnapshot、HistoryAnchor或不存在的NoEffectFinal。

恢复办理固定H14全部输入及协议语义版本，先H10保存，再发远端申请；远端裁定与本机安装各有稳定子OperationId。相同操作不同声明／主体／Use／修订拒绝OperationConflict，认证凭据更新只可证明同一原主体，不改业务意图。

本包不选择声明页面、供应商或账号找回流程。源身份可核验而目标新档角色不可对应时，可保留对原Grant的已成恢复；实际新用仍受M03映射及M06合法目标约束，不创建角色或改受益者。

## 6. 同一远端决定与竞争顺序

以下要求一个Grant的资格修订上条件裁定；表达持久能力，不指定数据库或租约。先验证主体及意图，再查询原操作／恢复业务键，最后核对当前状态。

1. 同OperationId同输入返回原结果；同ID异输入拒绝。已有(GrantId,UseId)恢复决定时，换OperationId也返回该原决定及当前资格查询依据，不再次恢复。
2. 首次申请核对准确Use仍是当前待确认使用、效果Unresolved、永久丢失声明及原用途，并比较预期资格修订。依据过时返回StaleContext，重新核对；不静默替换原固定输入。
3. 符合条件时，同一可查询持久RecoveryDecision写入：原Use授权被替代、原Grant可重新申请、资格新修订、输入及结果。不能拆成“先返机会后终止旧Use”或反过来留下半项。
4. 只有上述远端决定持久成立才Confirmed；超时为Unknown，先查原操作／业务键。返回准确原决定及其完成依据，不把客户端发出请求或服务端收到请求算成功。
5. 下一次玩家明确使用沿正常流程取得不同UseId，并以服务端当时修订核验；恢复本身不创建U2、不复活角色、不发卡或经验。恢复和新Use竞争时，排他条件必须共同成立。

决定的完成内容不可变；最新资格可能已被U2占用，查询原决定须分别给“原处置已完成”和“当前资格状态”。任何历史快照都不能使当前资格修订下降；同修订不同对象／内容为核对冲突，不按回执到达顺序猜。

| 先成立的事实／竞争输入 | 后来请求的条件结果 | 禁止的变化 |
| --- | --- | --- |
| 原U1的EffectCommitted先核验成立，再申请恢复 | 不适用例外；返回已知效果及当前已用状态 | 不以玩家声明抹掉已知效果，也不恢复一次。 |
| RecoveryDecision先成，再收到U1效果确认 | 保留准确旧效果历史及原决定，当前Grant／U2不变 | 不撤销恢复、不追扣机会，不把U1重新设当前占用。 |
| NoEffectFinal或正常撤回先释放U1，再申请恢复 | 返回已释放现状及原处置依据，不再执行恢复 | 不把已有可用资格加成两次；若已有U2，不释放U2。 |
| 两个恢复申请同时针对U1 | 同一业务键和修订只成一项；另一项查询同一决定 | 换OperationId或换设备不产生第二次返还。 |
| U2已许可／已用，再重试U1恢复或接收U1撤回 | 返回U1原决定／历史，当前投影保持U2 | 不按U1旧“可用”快照归零当前占用或加余额。 |
| 恢复申请与取消传输竞争 | 取消仅停止等待；查询原决定，已成仍沿原结果安装 | 不把取消当远端未成、正常释放或恢复撤销。 |

正常无效果释放、已有效果的正式撤回和政策恢复分别保存原因及依据。恢复先成时，后来的NoEffectFinal／撤回只补原U1历史，不做第二次可用变化；效果事实不能反向重写已成政策决定。

## 7. 本机安装、旧回执与新使用

远端恢复Confirmed后，M02按队列中的最新本机完整头组织M08候选：保留原决定、旧Use处置、当前已核验资格投影及待办；其他业务切片继承当前状态。只安装S12及办理引用，不恢复旧战斗、替换活动尝试、解除物品冻结或改HP／长期成长。

M08先比较同Grant的服务端修订。旧决定当时的可用快照只作历史：本机已知U2更高修订则保留U2；尚未取得当前状态则查询，离线只显示“恢复处置已成、当前资格待核对”。没有新查询证据不能把旧可用记录称为当前可用。

查询所得投影注明所依据修订；它仍不是下一次使用许可。任何新Use均再次联网条件申请。两设备在查询后竞争，服务端只受理当前修订下合法的一项；本机旧档、身份关联和普通选档均无权回写服务端资格。

本机候选一旦提交H10，expectedHead、候选、OperationId及CommitId固定。SaveFailed重试原候选；CommitUnknown先Lookup，不能换安装ID重办。确需改候选时先证明原意图未成并持久结束，再组织不同子操作；已成结果始终先查原记录。

H10完成才可报告“本机已记录此恢复处置”，另列当前资格状态；恢复远端已成而安装未成，不再向服务端重复返还。新使用可申请与本机角色已经复活是两个结果，不能合成一个成功提示。

M06已知U1被替代后，旧许可不能再产生新的复活候选；已成U1效果只作历史核对，不借安装恢复决定去回滚HP。S13原效果引用可对应S12的历史Use及处置；历史存在不代表U1仍是Grant当前占用。

本机回退遇U1已被替代，M06仍按合法历史恢复局面，M08只登记该准确历史撤回，不返当前机会或操作U2。对尚未获知处置的旧设备，不能承诺能删除其缓存或阻止所有离线变化；后来联网上报仅归原U1历史，不取得新的远端授权。

后续U2再次真实满足同一永久丢失判据，可按(GrantId,U2)独立恢复一次，再次新用另得U3。U1／U2各自防重，既不重复返U1，也不增加总次数上限、间隔等待或重新观看要求；普通失联仍不适用。
